Approachالمنهجية

The principles behind Baset UI and the architecture it is built toward. Sections describe design intent unless they say what exists today.

المبادئ التي تقوم عليها Baset UI والبنية التي تُبنى نحوها. تصف الأقسام نية التصميم ما لم تذكر ما هو موجود اليوم.

Design philosophyفلسفة التصميم

  • One implementation. Core components are not forked for React, Vue, Angular or Blade.تنفيذ واحد. لا تُنسخ المكونات الأساسية لكل من React وVue وAngular وBlade.
  • Progressive enhancement. Static components work without JavaScript whenever practical.تحسين تدريجي. تعمل المكونات الساكنة بلا جافاسكربت متى كان ذلك عمليًا.
  • Modularity. Components can be loaded and maintained independently.وحدات مستقلة. يمكن تحميل المكونات وصيانتها بشكل مستقل.
  • Design tokens. Shared appearance is controlled through CSS custom properties.Design Tokens. يُتحكم في المظهر المشترك عبر خصائص CSS المخصصة.
  • Accessible by default. Semantic HTML first, then keyboard behavior, focus management and ARIA where needed.إتاحة افتراضية. HTML دلالي أولًا، ثم سلوك لوحة المفاتيح وإدارة التركيز وARIA عند الحاجة.
  • Direction-aware. RTL and LTR are supported from the beginning.واعية بالاتجاه. دعم RTL وLTR منذ البداية.
  • No unnecessary dependencies. No mandatory runtime dependency and no mandatory build step.بلا اعتماديات غير ضرورية. لا اعتمادية تشغيل إلزامية ولا خطوة بناء إلزامية.
  • Honest support claims. Unfinished integrations and exports are labeled as such.صدق في الادّعاءات. التكاملات والتصديرات غير المكتملة تُوسَم كذلك.
  • Backward compatibility. Public classes, variables, methods and events change only with a documented migration path.توافق رجعي. لا تتغير الأصناف والمتغيرات والدوال والأحداث العامة إلا بمسار ترحيل موثَّق.

Framework agnostic architectureبنية مستقلة عن الأطر

The core uses platform standards and does not import React, Vue, Angular or Laravel. Markup uses normal HTML attributes and classes that any framework can render, and styles avoid selectors that depend on a framework's generated DOM.

تعتمد النواة على معايير المنصة ولا تستورد React أو Vue أو Angular أو Laravel. يستخدم الـ markup خصائص HTML وأصنافًا عادية يمكن لأي إطار عرضها، وتتجنب الأنماط المحددات التي تعتمد على DOM يولّده إطار بعينه.

A framework adapter is justified only when a component needs framework-specific lifecycle, state, refs or event integration. Such an adapter must be separately installable, depend on the core, clean up after itself, and never fork the component behavior. No adapter exists today.

يُبرَّر المحوّل فقط حين يحتاج المكوّن إلى تكامل مع دورة حياة الإطار أو حالته أو مراجعه أو أحداثه. ويجب أن يُثبَّت بشكل منفصل، ويعتمد على النواة، وينظّف ما ينشئه، ولا ينسخ سلوك المكوّن. لا يوجد أي محوّل اليوم.

Vanilla JavaScriptجافاسكربت خالصة

Not implemented yetغير منفَّذ بعد There is no JavaScript in the library yet. The rules future scripts must follow:

Not implemented yetغير منفَّذ بعد لا توجد جافاسكربت في المكتبة بعد. القواعد التي ستلتزم بها السكربتات مستقبلًا:

  • Plain JavaScript only; no framework and no eval().جافاسكربت خالصة فقط؛ بلا إطار ولا eval().
  • A global API, when one is appropriate, lives under the BUI namespace. A simple HTML/CSS component needs no global API.إن لزم API عام فيكون تحت مساحة الاسم BUI. المكوّن البسيط (HTML/CSS) لا يحتاج API عامًا.
  • Scope all work to the component's own element and never assume Baset UI owns the whole page.حصر كل العمل في عنصر المكوّن نفسه، وعدم افتراض أن Baset UI تملك الصفحة كلها.
  • Handle missing optional browser APIs gracefully.التعامل بسلاسة مع غياب واجهات المتصفح الاختيارية.

Progressive enhancementالتحسين التدريجي

Content and basic styling come from HTML and CSS. JavaScript is added only for behavior that HTML cannot provide, such as overlays and keyboard-driven widgets.

المحتوى والتنسيق الأساسي يأتيان من HTML وCSS. تُضاف جافاسكربت فقط للسلوك الذي لا يوفره HTML، مثل النوافذ المنبثقة والعناصر المعتمدة على لوحة المفاتيح.

This documentation site follows the same rule: the article text is plain HTML and stays readable without JavaScript. The menu, search, table of contents, copy buttons and the language, direction and theme switches need JavaScript, and without it the page is shown in English.

يتبع موقع التوثيق هذا القاعدة نفسها: نص المقالات HTML عادي ويبقى مقروءًا بلا جافاسكربت. أما القائمة والبحث وفهرس الصفحة وأزرار النسخ ومفاتيح اللغة والاتجاه والثيم فتحتاج إلى جافاسكربت، وبدونها تُعرض الصفحة بالإنجليزية.

Modular architectureالبنية المعيارية

A component owns its markup contract, styles, JavaScript (if any), options, events, documentation and tests. Shared code is extracted only when several components genuinely need it. Loading one component must not require loading all of them, and documentation or Playground code stays out of the runtime.

يملك المكوّن عقد الـ markup وأنماطه وجافاسكربت الخاصة به (إن وُجدت) وخياراته وأحداثه وتوثيقه واختباراته. لا يُستخرج كود مشترك إلا حين تحتاجه عدة مكونات فعلًا. تحميل مكوّن واحد يجب ألا يتطلب تحميلها كلها، ويبقى كود التوثيق وPlayground خارج بيئة التشغيل.

CSS architectureبنية CSS

Foundation (pre-release)أساس أولي (تمهيدي) The token layer exists today. Component styles are planned.

Foundation (pre-release)أساس أولي (تمهيدي) طبقة الـ tokens موجودة اليوم. أنماط المكونات مخططة.

  • Class prefix bui-, custom property prefix --bui-.بادئة الأصناف bui-، وبادئة الخصائص المخصصة --bui-.
  • Shared values live in tokens. Components consume semantic tokens such as --bui-color-surface instead of hardcoding colors, so one theme switch restyles everything.القيم المشتركة تعيش في tokens. تستهلك المكونات tokens دلالية مثل --bui-color-surface بدل ترميز الألوان مباشرة، فيعيد تبديل الثيم تنسيق كل شيء.
  • Direction-sensitive layout uses CSS logical properties (see below).التخطيط المتأثر بالاتجاه يستخدم الخصائص المنطقية في CSS (انظر أدناه).
  • Component styles are scoped to bui- classes. No broad selectors such as button or * and no !important unless a documented compatibility problem requires it. The current stylesheet contains no element selectors and no resets.تُحصر أنماط المكونات في أصناف bui-. بلا محددات واسعة مثل button أو * وبلا !important إلا لمشكلة توافق موثقة. الملف الحالي لا يحتوي محددات عناصر ولا reset.
  • Customizing one instance must not restyle every instance: override tokens on a wrapper element. This already works for tokens; see How to customize.تخصيص نسخة واحدة يجب ألا يغيّر كل النسخ: تُعدَّل الـ tokens على عنصر مغلِّف. هذا يعمل اليوم مع الـ tokens؛ انظر طريقة التخصيص.
  • Motion durations are tokens and become zero under prefers-reduced-motion: reduce.مدد الحركة tokens وتصبح صفرًا عند prefers-reduced-motion: reduce.

Component class naming is not fixed yetتسمية أصناف المكونات لم تُحسم بعد

The exact naming pattern after the bui- prefix will be settled when the first component, Button, is specified. Until then no component class names are documented.

سيُحسم نمط التسمية بعد البادئة bui- عند توصيف أول مكوّن وهو Button. إلى ذلك الحين لا تُوثَّق أسماء أصناف للمكونات.

RTL and LTR supportدعم RTL وLTR

Direction is controlled by the standard dir attribute on <html> or on any element. Layout uses CSS logical properties so a single rule works in both directions:

يُتحكم في الاتجاه عبر الخاصية القياسية dir على <html> أو أي عنصر. يستخدم التخطيط الخصائص المنطقية في CSS ليعمل قالب واحد في الاتجاهين:

Instead ofبدلًا من Useاستخدم
margin-left, margin-rightmargin-inline-start, margin-inline-end
padding-left, padding-rightpadding-inline-start, padding-inline-end
left, rightinset-inline-start, inset-inline-end
border-leftborder-inline-start
text-align: lefttext-align: start
.panel {
  padding-inline: var(--bui-space-4);
  border-inline-start: 4px solid var(--bui-color-primary);
  text-align: start;
}

Other rules: do not blindly apply row-reverse; do not force text or controls to LTR; give direction-sensitive icons and keyboard behavior explicit RTL handling; test with Arabic and English labels.

قواعد أخرى: لا تستخدم row-reverse دون تفكير؛ لا تجبر النص أو العناصر على LTR؛ عالج الأيقونات وسلوك لوحة المفاتيح المتأثرة بالاتجاه صراحةً؛ واختبر بتسميات عربية وإنجليزية.

You can see this in action here: switch language or press the RTL button in the top bar. The sidebar, breadcrumbs and previous/next links mirror, while code blocks stay left-to-right.

يمكنك رؤية ذلك هنا: بدّل اللغة أو اضغط زر RTL في الشريط العلوي. تنعكس الشريط الجانبي ومسار التنقل وروابط السابق/التالي، بينما تبقى كتل الشيفرة من اليسار إلى اليمين.
