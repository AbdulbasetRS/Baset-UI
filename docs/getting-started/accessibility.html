Accessibilityإمكانية الوصول

Accessibility principles for Baset UI, the contrast of today's tokens measured from the real values, how to use this site with a keyboard, and an honest account of what has and has not been tested.

مبادئ إمكانية الوصول في Baset UI، وتباين الـ tokens الحالية مقيسًا من القيم الفعلية، وكيفية استخدام هذا الموقع بلوحة المفاتيح، وبيان صريح بما اختُبر وما لم يُختبر.

No conformance claimلا ادّعاء بالمطابقة

Baset UI makes no WCAG conformance claim. No components exist yet, and no accessibility audit has been performed. This page records principles and measurements, not certification.

لا تدّعي Baset UI المطابقة لأي مستوى من WCAG. لا توجد مكونات بعد، ولم يُجرَ أي تدقيق لإمكانية الوصول. تسجّل هذه الصفحة مبادئ وقياسات، وليست شهادة.

Accessibility philosophyفلسفة إمكانية الوصول

Accessibility is part of the definition of done for every component, not a later pass. A component is not complete because it looks right; it must also work with a keyboard, expose its state, and keep visible focus.

إمكانية الوصول جزء من تعريف الإنجاز لكل مكوّن وليست مرحلة لاحقة. المكوّن لا يكتمل لأن شكله سليم؛ بل يجب أن يعمل بلوحة المفاتيح، ويكشف حالته، ويحافظ على تركيز مرئي.

  • Semantic HTML first; ARIA only when native semantics are not enough.HTML دلالي أولًا؛ وARIA فقط حين لا تكفي الدلالات الأصلية.
  • Every interactive widget works with the keyboard.كل عنصر تفاعلي يعمل بلوحة المفاتيح.
  • Focus is always visible and managed correctly for overlays.التركيز دائمًا مرئي ويُدار بشكل صحيح للنوافذ المنبثقة.
  • Never communicate state by color alone.لا تنقل الحالة بالألوان وحدها.
  • Respect reduced-motion preferences.احترام تفضيل تقليل الحركة.

You needتحتاج Useاستخدم
An action (save, open, toggle)إجراء (حفظ، فتح، تبديل)<button type="button">
Navigation to another page or sectionتنقل إلى صفحة أو قسم آخر<a href>

Tabular dataبيانات جدولية<table> with <th scope>

<!-- Prefer -->
<button type="button">Save</button>

<!-- Avoid: not focusable, no role, no keyboard support -->
<div class="clickable">Save</div>

This site follows the same rule: landmarks (header, nav, main, aside, footer), real headings in order, real tables and real buttons. Each block of content carries a lang attribute, and the language that is not active is removed from the page, so a screen reader does not read both.

يتبع هذا الموقع القاعدة نفسها: معالم الصفحة (header وnav وmain وaside وfooter)، وعناوين حقيقية مرتبة، وجداول وأزرار حقيقية. وتحمل كل كتلة محتوى الخاصية lang، وتُزال اللغة غير الفعالة من الصفحة حتى لا يقرأ قارئ الشاشة اللغتين معًا.

Focus managementإدارة التركيز

  • Visible focus uses :focus-visible with the --bui-focus-ring-width and --bui-focus-ring-offset tokens, in the primary color.يستخدم التركيز المرئي :focus-visible مع tokens ‏--bui-focus-ring-width و--bui-focus-ring-offset وبلون العلامة.
  • Search is a native <dialog> opened with showModal(). Focus moves into it, Escape closes it, and focus returns to where it was.البحث عنصر <dialog> أصلي يُفتح بـ showModal(). ينتقل التركيز إليه، ويغلقه Esc، ويعود التركيز إلى موضعه السابق.
  • On small screens, opening the menu moves focus into it and makes the page content inert. Closing it returns focus to the menu button.على الشاشات الصغيرة، يؤدي فتح القائمة إلى نقل التركيز إليها وجعل محتوى الصفحة غير تفاعلي (inert). وإغلاقها يعيد التركيز إلى زر القائمة.
  • Future overlays (modal, dropdown, popover) must manage focus the same way. This is a requirement, not an implementation.يجب أن تدير النوافذ المنبثقة المستقبلية (modal وdropdown وpopover) التركيز بالطريقة نفسها. هذا شرط وليس تنفيذًا.

ARIA attributesخصائص ARIA

ARIA is used on this site only where native elements do not express the state. ARIA state must always match the real state.

تُستخدم ARIA في هذا الموقع فقط حيث لا تعبّر العناصر الأصلية عن الحالة. ويجب أن تطابق حالة ARIA الحالة الحقيقية دائمًا.
