Global CSS variablesمتغيرات CSS العامة

Foundation (pre-release)أساس أولي (تمهيدي) Tokens are CSS custom properties named --bui-{category}-{name}. Load the stylesheet, then read them with var() anywhere:

Foundation (pre-release)أساس أولي (تمهيدي) الـ tokens خصائص CSS مخصصة بأسماء على الشكل --bui-{الفئة}-{الاسم}. حمّل ملف الأنماط ثم اقرأها بـ var() في أي مكان:

.card {
  padding: var(--bui-space-4);
  border: var(--bui-border-width) solid var(--bui-color-border);
  border-radius: var(--bui-radius-lg);
  background: var(--bui-color-surface);
  box-shadow: var(--bui-shadow-sm);
}

Pre-releaseنسخة تمهيدية

Names and values can still change before the first release, and there are no version tags yet. Only tokens that this site or a planned component actually uses are defined.

قد تتغير الأسماء والقيم قبل الإصدار الأول، ولا توجد وسوم إصدارات بعد. لا تُعرَّف إلا الـ tokens التي يستخدمها هذا الموقع أو مكوّن مخطَّط فعلًا.

The values in the tables below are read live from the stylesheet loaded on this page (a static copy is shown when JavaScript is off). They are not typed by hand.

القيم في الجداول أدناه تُقرأ مباشرة من ملف الأنماط المحمَّل في هذه الصفحة (وتظهر نسخة ثابتة عند تعطيل جافاسكربت). لم تُكتب يدويًا.

Not defined yetغير معرَّف بعد

A secondary color, a z-index scale, breakpoints and component-level variables (for example per-button variables) do not exist. Breakpoints cannot be CSS variables anyway, because custom properties cannot be used inside media queries.

لا يوجد لون ثانوي ولا مقياس z-index ولا نقاط توقف ولا متغيرات على مستوى المكوّن (مثل متغيرات خاصة بالزر). ونقاط التوقف لا يمكن أن تكون متغيرات CSS أصلًا، لأن الخصائص المخصصة لا تُستخدم داخل media queries.

Theme variablesمتغيرات الثيم

The theme-independent tokens are defined on :root. Color and shadow tokens come in two sets: the light set on :root and .bui-light (the default), and the dark set on .bui-dark. Each set also declares color-scheme.

الـ tokens غير المرتبطة بالثيم معرَّفة على :root. أما الألوان والظلال ففي مجموعتين: الفاتحة على :root و.bui-light (الافتراضية)، والداكنة على .bui-dark. وتعلن كل مجموعة قيمة color-scheme أيضًا.

Add the class to <html> for a page-wide theme, or to any element for a scoped region:

أضف الصنف إلى <html> لثيم يشمل الصفحة، أو إلى أي عنصر لمنطقة محصورة:

<html class="bui-dark"> ... </html>

<section class="bui-dark">
  This region uses the dark tokens.
</section>

The stylesheet does not switch themes by itself, and it does not read or write browser storage. Deciding when to add bui-dark is up to your page. For example, to follow the operating system setting:

لا يبدّل ملف الأنماط الثيم من تلقاء نفسه ولا يقرأ التخزين في المتصفح أو يكتب فيه. قرار إضافة bui-dark متروك لصفحتك. مثلًا لاتباع إعداد نظام التشغيل:

var prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
document.documentElement.classList.toggle('bui-dark', prefersDark);

This documentation site additionally remembers the reader's choice in localStorage under the key bui-theme. That behavior belongs to the docs site, not to the library.

يحفظ موقع التوثيق هذا أيضًا اختيار القارئ في localStorage تحت المفتاح bui-theme. هذا السلوك يخص موقع التوثيق وليس المكتبة.

How to customize variablesطريقة تخصيص المتغيرات

Override globallyتخصيص عام

Load your own stylesheet after baset-ui.css and override the tokens you want. Override color tokens in both themes:

حمّل ملف أنماطك بعد baset-ui.css وعدّل الـ tokens التي تريدها. عدّل tokens الألوان في الثيمين:

/* my-theme.css, loaded after baset-ui.css */
:root {
  --bui-color-primary: #7c3aed;
  --bui-color-primary-hover: #6d28d9;
}

.bui-dark {
  --bui-color-primary: #a78bfa;
  --bui-color-primary-hover: #c4b5fd;
}

Why both blocks?لماذا الكتلتان؟

:root and .bui-dark have the same specificity, so the later rule wins. If you only override :root after the stylesheet, your value also wins in dark mode, and the dark theme will use your light color.

للمحددين :root و.bui-dark الخصوصية نفسها، فتفوز القاعدة الأحدث. إن عدّلت :root فقط بعد ملف الأنماط فستفوز قيمتك في الوضع الداكن أيضًا، وسيستخدم الثيم الداكن لونك الفاتح.

Override for one regionتخصيص لمنطقة واحدة

Custom properties are inherited, so setting a token on a wrapper changes only what is inside it:

الخصائص المخصصة تُورَّث، لذا فضبط token على عنصر مغلِّف يغيّر ما بداخله فقط:

.my-scope {
  --bui-color-primary: #7c3aed;
  --bui-radius-md: 0.75rem;
}

Notice that choosing Dark in the preview does not change your primary color: an override set directly on an element beats the theme class on the same element. That is the same reason you need both blocks when overriding globally.

لاحظ أن اختيار داكن في المعاينة لا يغيّر لونك الأساسي: التعديل المضبوط مباشرة على العنصر يتفوق على صنف الثيم على العنصر نفسه. وهذا هو السبب نفسه الذي يجعلك تحتاج الكتلتين عند التعديل العام.

Before you ship a custom colorقبل اعتماد لون مخصص

  • Check that --bui-color-on-primary still reaches 4.5:1 on your new primary. The demo above reports the ratio.تأكد أن --bui-color-on-primary ما زال يحقق 4.5:1 على لونك الأساسي الجديد. يعرض العرض أعلاه النسبة.
  • Provide the dark-theme values as well.قدّم قيم الثيم الداكن أيضًا.
  • Do not rename tokens; override their values.لا تغيّر أسماء الـ tokens؛ عدّل قيمها.
