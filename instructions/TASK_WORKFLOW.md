## مرحلة التسليم: Preview + ZIP (إلزامية بعد كل مهمة)

بعد انتهاء الاختبارات وتحديث الملفات، تُنفذ هذه الخطوات بالترتيب. الهدف: يعاين المستخدم النتيجة داخل Claude قبل تحميل أي شيء، ثم يحمّل المشروع كاملاً بضغطة واحدة.

### أ) Preview داخل Claude
1. أنشئ نسخة Preview من الموقع في ملف HTML **واحد مستقل** (يُنشر Artifact كصفحة واحدة ولا يستطيع تحميل ملفات المشروع الأخرى): ضمّن محتوى `assets/css/*.css` و`documentation/assets/css/*.css` داخل `<style>` ومحتوى ملفات JS داخل `<script>` بنفس ترتيب التحميل في `index.html`، وأي صور أو خطوط كـ `data:` URIs.
2. ملف الـ Preview **أداة تسليم مؤقتة**: لا يُضاف إلى المستودع ولا يُسلَّم ضمن ملفات المشروع، ولا يُعدّل كأنه مصدر. المصدر الوحيد هو ملفات المشروع.
3. انشره بأداة Artifact (publish) وأعطِ المستخدم رابط المعاينة. عند تعديل لاحق في نفس المحادثة حدّث نفس الـ Artifact بدل إنشاء جديد.
4. اذكر بصدق أي فرق بين الـ Preview والموقع الفعلي (مثل صفحات توثيق متعددة لا يمكن التنقل بينها داخل الـ Preview، وتُعرض الصفحة المعنية بالمهمة أو صفحات مجمّعة في Preview واحد). لا تدّعِ أن الـ Preview هو الموقع المنشور.

### ب) ملف ZIP كامل
1. اضغط **المشروع كاملاً** (كل المجلدات والملفات المخفية المطلوبة مثل `.nojekyll` و`.gitignore`) في `Baset-UI.zip`، بحيث يفك إلى مجلد جذر واحد `Baset-UI/`.
2. استبعد: ملفات Preview المؤقتة، `node_modules/`، ملفات النظام (`.DS_Store`)، وأي ملفات تجريبية خارج المعمارية.
3. تأكد بعد الضغط أن الـ ZIP يفتح ويحتوي `index.html` في جذر المجلد وكل ملفات `instructions/`.
4. سلّم الـ ZIP بأداة `present_files` ليكون زر تحميل واحد.

### ج) بعد التحميل (يفعلها المستخدم)
رفع الملفات إلى المستودع https://github.com/AbdulbasetRS/Baset-UI ثم تفعيل Pages لعرضها على https://abdulbasetrs.github.io/Baset-UI/. الـ Claude لا يدّعي أن النشر تم، فهو لا يملك وصولاً للمستودع.

## محتوى التقرير النهائي
- ملخص ما أُنجز.
- الملفات المنشأة/المعدلة.
- القرارات المعمارية الجديدة (إن وجدت) وأسبابها.
- الاختبارات المنفذة ونتائجها، وما لم يُختبر.
- ما تُرك عمداً خارج النطاق، وأي مخاطر أو أسئلة مفتوحة.
