Calendar & Scheduler

A full scheduler in plain JavaScript: month, week and day views, events you can add, edit, delete, drag and resize, overlapping events side by side, categories and colors, English and Arabic with real RTL, light and dark, keyboard and touch. Every demo below is live, and every code box is complete: copy it into a page and it runs.

14 examples

Quick start

The calendar is two files you already know: baset-ui.css (section 23) and the optional, dependency-free baset-calendar.js. There is no build step. All times are local wall-clock times; event dates are plain strings like "2026-11-04T10:00:00", and all-day events use date-only strings (the end day is included).

index.html
<!-- in <head> -->
<link rel="stylesheet" href="assets/css/baset-ui.css">

<!-- where you want the calendar -->
<div id="calendar"></div>

<!-- before </body> -->
<script src="assets/js/baset-calendar.js"></script>
<script>
  const calendar = BUI.calendar('#calendar', {
    view: 'month',
    events: [{ title: 'Launch', start: '2026-11-10T09:00:00', end: '2026-11-10T10:30:00', color: 'primary' }],
    onEventUpdate: (event) => console.log('saved', event),
  });
</script>

<!-- or declare it, no JavaScript needed -->
<div data-bui-calendar data-bui-view="week" data-bui-locale="ar" data-bui-events='[{"title":"Meeting","start":"2026-11-04T10:00:00"}]'></div>

Drag and drop move events · drop preview · touch
Drag an event, then drop it.
Drag an event to another day (month) or another time and day (week and day views). A card follows the pointer, a dashed ghost or a highlighted day shows where it will land, and the date and time update when you drop it. Text is never selected while dragging. On a phone or tablet, press and hold an event for a moment, then drag. Keyboard: focus an event and press Alt + arrow keys. Press Esc while dragging to cancel.

Resize events drag the top or bottom edge
Drag the bottom edge of an event.
In week and day views every event has a handle on its top and bottom edge. Drag the bottom edge to change the end time or the top edge to change the start; the duration snaps to snap minutes and the ghost shows the new range. On touch screens the handles respond immediately. Set resizable: false to turn it off, or editable: false on one event to lock it.

The event object

Events go in with events or addEvent() and come out of getEvents(), callbacks and DOM events in the same format.

FieldMeaning
idUnique id (number or string). Created for you if missing.
titleText shown on the event.
descriptionLonger text, shown in the details popup.
start"2026-11-04T10:00:00" local time (no time zone), or a date-only string for all-day events. A Date is accepted too.
endSame format. Missing end: start + defaultDuration. For all-day events the end day is included.
allDaytrue for all-day events (date-only start / end also make an all-day event).
colorprimary · secondary · success · danger · warning · info, or any CSS color. Default: the category color, then primary.
categoryA categories[].value, or any text.
editablefalse locks this one event (no drag, resize, edit or delete).
anything elseExtra properties are kept and returned by getEvents(), for example { roomId: 7 }.

Callbacks and events

Three ways to listen, all with the same arguments: an option callback (onEventUpdate), a handler (calendar.on("eventUpdate", fn)) and a DOM event on the container (bui:cal-eventupdate, with event.detail.args). They fire for user actions; the API methods only fire change.

Option callbackon() nameDOM eventWhen
onEventClick(event, jsEvent)eventClickbui:cal-eventclickAn event was clicked or activated with Enter / Space. Return false to skip the built-in popup.
onEventCreate(event)eventCreatebui:cal-eventcreateThe dialog saved a new event. Return false to refuse it (for example after server validation).
onEventUpdate(event, oldEvent, info)eventUpdatebui:cal-eventupdateAn event changed by the dialog, a drag, a resize or the keyboard. info.source is "edit", "drag", "resize" or "keyboard". Return false to put it back.
onEventDelete(event)eventDeletebui:cal-eventdeleteDelete was confirmed. Return false to keep the event.
onDateClick(date, jsEvent, info)dateClickbui:cal-dateclickA day, a day header or an empty time slot was clicked (date includes the slot time). Return false in month view to skip the new-event dialog.
onViewChange(view, info)viewChangebui:cal-viewchangeThe view changed, from the toolbar or setView(). info has title, date, start, end.
onNavigate(date, view, range)navigatebui:cal-navigateThe visible period changed (prev, next, today, setDate, keyboard).
—changebui:cal-changeAny change to the event list: { type: "add" | "update" | "remove" | "set", event, source }. Also fired by the API methods.

Arabic, RTL and dark mode

The stylesheet uses logical properties only (inset-inline-start, margin-inline, border-inline-start), so a calendar inside dir="rtl" mirrors fully: weekday order, the toolbar and its chevrons, the hour column, event stripes and handles. Layout decisions in JavaScript (arrow keys, slide animation) read the computed direction, and names, digits and times use Intl.DateTimeFormat with the Gregorian calendar, so the grid and the labels always agree. Colors come from --bui-* tokens with light-dark(), so class="bui-dark" on <html> (or color-scheme on one calendar) switches the theme. On narrow containers (under 640px wide) the month grid shows colored dots instead of titles; tap a day to see its events.
