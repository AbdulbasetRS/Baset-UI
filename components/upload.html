File upload

A drop zone for the native file input: drag and drop, image previews, a tidy file list or grid, checks for type, size and count, and real uploads with progress and retry. The input keeps its files, so normal forms keep working.

19 examples

Quick start

Add data-bui-upload to a native <input type="file"> and load baset-upload.js after the stylesheet. The script wraps the input in a drop zone, shows the chosen files, checks them and, if you configure a server, uploads them. The native input stays in the page and stays the source of truth: id, name, accept, multiple, required, disabled, capture and form work as before, and the keyboard opens the file dialog. Only the files that passed the checks are in input.files (the script keeps it in sync with DataTransfer), so a normal form submit sends exactly the listed files, and a removed file is not sent. It has no dependencies and does not need baset-ui.js.

index.html
<link rel="stylesheet" href="assets/css/baset-ui.css">
<script src="assets/js/baset-upload.js" defer></script>

<label class="bui-upload-caption" for="cv">CV (PDF or Word, up to 5 MB)</label>
<input type="file" id="cv" name="cv" accept=".pdf,.doc,.docx" data-bui-upload data-bui-max-size="5MB">

Choosing is not uploading. A file is shown as uploaded only after your server answered. Without data-bui-url (or BUI.upload.configure) the component only selects and checks files, and the form sends them when it is submitted. Always set accept: without it every file type is allowed. Dropped files are checked against it too, because the browser applies accept only in its own dialog.

Checking the files

Every rule gives a clear message, in the language of the nearest lang (English and Arabic are built in; see Texts below). A file that fails is listed with its reason and is not added to input.files. Rules: accept · data-bui-max-size · data-bui-min-size · data-bui-max-files · data-bui-min-files (checked by form validation, so the form cannot be submitted with too few) · required.

Uploading to a server

Set data-bui-url and the script sends one request per file (multipart/form-data, field name from data-bui-field or the input name) with real progress, a Cancel button while sending and a Retry button after a failure. Add data-bui-auto to start as soon as files are chosen; otherwise an Upload button appears. For headers, extra fields, cookies or your own request code use BUI.upload.configure(input, { … }). For AJAX-only uploads leave name off the input, so the form does not send the same files again.

JavaScript (demo server)
// This documentation page has no server, so these two demos use a simulated one that runs in the browser
// (no file leaves your computer). Name a file "fail" to see the error and the Retry button.
// In your project use data-bui-url="/api/upload" instead, or BUI.upload.configure(input, { url: '/api/upload', headers: { ... } }).
const tried = new WeakSet();
function simulatedServer(file, { onProgress, signal }) {
  return new Promise((resolve, reject) => {
    const failOnce = /fail/i.test(file.name) && !tried.has(file);
    tried.add(file);
    let sent = 0;
    const timer = setInterval(() => {
      sent += Math.max(file.size / 12, 30000);
      onProgress(sent / file.size);
      if (failOnce && sent / file.size > 0.5) { clearInterval(timer); reject(new Error('Server error 500')); }
      else if (sent >= file.size) { clearInterval(timer); resolve({ ok: true }); }
    }, 120);
    signal.addEventListener('abort', () => { clearInterval(timer); reject(new DOMException('Aborted', 'AbortError')); });
  });
}
BUI.upload.configure('#up-server', { uploader: simulatedServer });
BUI.upload.configure('#up-auto', { uploader: simulatedServer });

Texts and languages

Messages use {name}, {size}, {max}, {min}, {n}, {types}. English and Arabic are built in. Add or change a language, missing keys fall back to English: BUI.upload.locales.fr = { title1: 'Glissez un fichier ici', titleN: 'Glissez des fichiers ici', type: '« {name} » n\'est pas autorisé. Types : {types}.', … }. Keyboard and screen readers

KeysAction
Tab · Shift + TabFocus the zone (a focus ring appears), then each Retry / Remove / Upload / Clear button
Enter · Space on the zoneOpen the file dialog (native behavior of the file input)
Enter · Space on a buttonRemove, cancel, retry, upload or clear. After a removal the focus moves to the next Remove button, or back to the zone

The zone is the <label> of the real input; the hint and the message are linked with aria-describedby; errors and results are announced through a polite live region; every button names its file (Remove report.pdf); progress bars are role="progressbar"; the list is named Selected files. Browsers without the DataTransfer constructor cannot edit input.files: there the component still selects, checks and previews, but the single-file Remove button is hidden before upload, and rejected files cannot be kept out of the form.
