Date & time pickers

One look for date, time, date and time, month and week fields. The native input stays your source of truth (value, min, max, step, validation, forms); a light, accessible popup replaces the browser's own, in light and dark, LTR and RTL.

14 examples

Quick start

Add data-bui-datetime to a native <input> of type date, time, datetime-local, month or week, and load baset-datetime.js after the stylesheet. The native input stays in the page and stays the source of truth: id, name, value, min, max, step, required, disabled, readonly, validation and form submit work exactly as before, and you can still type into it. The picker is the part the browser does not let CSS change: a calendar and time lists built with JavaScript. It writes the value in the native format and fires input and change. It does not need baset-ui.js and has no dependencies.

index.html
<link rel="stylesheet" href="assets/css/baset-ui.css">
<script src="assets/js/baset-datetime.js" defer></script>

<!-- the field -->
<input type="date" class="bui-input" name="birthday" data-bui-datetime>

Inputs added later (for example by your framework or after a fetch) are found automatically. To set one up yourself: BUI.datetime.init(container).

The five types

Floating-label fields date · time · datetime-local · month · week
Click anywhere on the field (or the icon), or focus it and press Alt + ↓ or F4. To type instead, reach the field with Tab, or set data-bui-click-open="false" so only the icon opens the picker. Picking a day, month or week closes the popup; time lists stay open until Done or Esc.

Minimum, maximum and step

The popup reads min, max and step from the input every time it opens, so you can change them with JavaScript at any time. Days, months, years, hours and minutes that are not allowed are dimmed and cannot be chosen, and the arrows stop at the limits. The browser still validates the value, so :invalid, validity.rangeUnderflow and the form message work.

Language, locale and clock

Month and day names, digits, the first day of the week and the 12 / 24-hour clock come from the browser locale for the nearest lang attribute (or data-bui-locale). The words of the buttons are in English and Arabic; add another language in one object, as in the French example below (missing keys fall back to English). The format of the native field itself (for example mm/dd/yyyy) is chosen by the browser from the user's own settings.

Locale, first day, week numbers data-bui-locale · data-bui-first-day · data-bui-hour12 · data-bui-week-numbers
The week picker always starts on Monday (ISO 8601) and shows week numbers.

Values, limits and events BUI.datetime · bui:datetime-open · bui:datetime-close

JavaScript
const input = document.getElementById('dt-api');
const log = (text) => { logBox.textContent = text + '\n' + logBox.textContent; };
const logBox = document.getElementById('dt-api-log');

['input', 'change', 'bui:datetime-open', 'bui:datetime-close'].forEach((name) =>
  input.addEventListener(name, () => log(name + (name === 'change' ? '  ->  ' + input.value : ''))));

// set the value from code: tell the picker (and your own listeners) with input + change, as the browser does for users
document.getElementById('dt-api-set').onclick = () => {
  input.value = '2026-11-01T10:00';
  input.dispatchEvent(new Event('input', { bubbles: true }));
  input.dispatchEvent(new Event('change', { bubbles: true }));
};
document.getElementById('dt-api-min').onclick = () => input.setAttribute('min', '2026-11-05T00:00'); // read again at the next open
document.getElementById('dt-api-open').onclick = () => BUI.datetime.open(input);
document.getElementById('dt-api-clear').onclick = () => { input.value = ''; input.dispatchEvent(new Event('change', { bubbles: true })); };

Attributes

AttributePurpose
data-bui-datetimeTurns the picker on for this input. On a type="text" input give the kind: data-bui-datetime="week"
min · max · stepNative limits, read each time the picker opens. step="any" allows every value
required · disabled · readonlyNative. Required hides Clear; disabled and read-only cannot open the picker
valueThe native format: 2026-10-29 · 14:30 or 14:30:15 · 2026-10-29T14:30 · 2026-10 · 2026-W44
data-bui-locale="fr-FR"Language of the names and digits (default: nearest lang). Add -u-nu-latn for Western digits: ar-EG-u-nu-latn
data-bui-first-day="1"First day of the week, 0 (Sunday) to 6 (Saturday). Default from the locale; the week picker always uses Monday
data-bui-hour12="true | false"12-hour or 24-hour time lists (default from the locale)
data-bui-week-numbersShow ISO week numbers beside the days
data-bui-size="sm | lg"Size of the popup
data-bui-mode="popover | sheet"Force one layout (default: popup, bottom sheet up to 560 px wide)
data-bui-click-open="false"Open only from the button. By default a click anywhere on the field opens the picker
data-bui-popup-class="a b"Extra classes on the popup, for custom colors

Keyboard and screen readers

KeysAction
Alt + ↓ or F4 on the field · Enter / Space on the buttonOpen the picker. Focus moves to the selected day (or today, or the selected time)
← → ↑ ↓Move one day or one week. They follow the reading direction in RTL
Home · EndFirst or last day of the week
PageUp · PageDown · with ShiftPrevious or next month · previous or next year
Enter · SpaceChoose the focused day, month, year or time
Time lists: ↑ ↓ · ← → · Home · EndMove in a list · move to the next list · first or last value
Tab · Shift + TabMove through the controls; the focus stays inside the popup while it is open
EscClose and return the focus to where it was

The popup is a role="dialog" named after the field, the calendar is a grid with full date names on every day, the current month is announced when it changes, and every control has an accessible name. The focus ring is always visible. Where the browser has no native month or week input it shows a text box: the picker still works, and it checks the typed text (YYYY-MM, YYYY-Www) against min and max itself.
