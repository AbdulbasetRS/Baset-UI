const form = document.getElementById('wizard');

// Step 3: show what was typed
form.addEventListener('bui:stepper-change', (e) => {
  if (e.detail.to !== 2) return;
  const f = new FormData(form);
  document.getElementById('wz-summary').innerHTML =
    `<li>Name: ${f.get('wz-name')}</li><li>Email: ${f.get('wz-email')}</li><li>Role: ${f.get('wz-role')}</li>`;
});

// The Finish button validates every step, then submits the form
form.addEventListener('submit', (e) => {
  e.preventDefault();   // send the data with fetch() here, then:
  wizard.complete();
});

    const invite = BUI.stepper('#invite', {

    Markup

    Class / attributeUse
    .bui-stepperThe container. Use a <form> for multi-step forms, or a <div>.
    .bui-stepper-listThe <ol> that holds the steps.
    .bui-stepOne step (<li>). States: .bui-step-active, .bui-step-done, .bui-step-error.
    .bui-step-headMarker and text. A <button> makes the step clickable; a <span> keeps it static.
    .bui-step-markerThe circle: a number, an icon or any short text.
    .bui-step-text, -title, -descThe label and the optional description.
    .bui-stepper-vertical, -sm, -lgVertical layout and sizes.
    .bui-stepper-panelContent of one step, in the same order as the steps. It may sit inside its .bui-step (vertical).
    .bui-stepper-actionsRow for the buttons. Add data-bui-step-prev, -next, -finish or -reset to a button.
    .bui-stepper-countFilled with “2 / 3”.
    [data-bui-stepper-done]A block shown after complete(); use .bui-stepper-done for the centered look.

    Options

    OptionDefaultDescription
    start0Index of the first step to show. Earlier steps are marked done.
    lineartrueJumping ahead validates every step in between and stops at the first invalid one. false allows free navigation.
    clickabletruetrue: all step buttons work. 'done': only completed steps and the current one. false: none.
    validatetruefalse turns validation off. A function (index, panel, stepper) runs after the built-in field checks and returns true, false or an error text (a promise is fine).
    beforeChangenull(to, from, stepper); return false (or a promise of it) to cancel the move.
    onChange, onInvalid, onFinishnullCallbacks: (to, from, stepper), (index, stepper), (stepper).
    animatetrueSlide and fade the panel in (off with reduced motion).
    focustrueMove focus to the new panel after a step change.
    enterKeytruePressing Enter in a field goes to the next step, or finishes on the last one.
    labels{…}Screen-reader texts: status (“Step {n} of {total}: {title}”) and complete.

    Every option also has a data attribute: data-bui-start, data-bui-linear="false", data-bui-clickable="done|false", data-bui-validate="false" (on a panel it skips that panel), data-bui-animate="false", data-bui-enter-key="false".

    Methods and events

    MemberWhat it does
    BUI.stepper(target, options)Creates a wizard (new is optional) and returns it. Returns the existing one if the element already has a stepper.
    BUI.stepper.get(el), .init(root)Find an instance; start every [data-bui-stepper] inside root (done automatically on load).
    next(), prev(), goTo(i)Move. They return a promise with true when the step changed.
    validate(i)Validate one step and mark it done or error. Returns a promise with a boolean.
    finish()Validate every step, fire bui:stepper-finish, then submit the form (requestSubmit()) or call complete().
    complete(), reset(clearForm)Mark everything done and show the done block; or start again (and reset the form when true).
    setState(i, state)'done', 'error' or '': for example after a server-side check.
    current, count, statesCurrent index, number of steps, and the state of each step.
    bui:stepper-changeEvent with detail.from and detail.to.
    bui:stepper-invalidA step failed validation: detail.index.
    bui:stepper-finishCancelable. Call preventDefault() to handle the submit yourself.

    Accessibility and keyboard

    The list is an <ol>, the current step has aria-current="step", step buttons point to their panels with aria-controls, and a live region announces “Step 2 of 3”. Tab reaches the step buttons, ← → (or ↑ ↓ when vertical, mirrored in RTL) move between them, Home and End jump to the first and last. Markers use text as well as color, so error and completed steps are not shown by color alone.
