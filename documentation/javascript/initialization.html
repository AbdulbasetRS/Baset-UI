Initialization

How components are registered, initialized from HTML or JavaScript, and destroyed.

Overview

Every component with JavaScript follows the same lifecycle. The core owns the parts that are identical for all components: finding the element, reading and validating options, creating the instance once, remembering it, and removing it on destroy.

Lifecycle
StepWho does itWhat happens
Create / InitCoreOptions are resolved (Defaults, then HTML attributes, then JS options). create() runs once per element and component.
MountComponentInside create(): ARIA, listeners, initial state.
UpdateComponentMethods such as update() and refresh() on the instance.
DestroyComponent and coreThe component removes everything it added. The core removes the instance from its registry.

Note

The core ships no component. The examples use my-widget as a placeholder name for a component that you register yourself. The snippets are not live demos. A runnable check of every behavior described here is tests/manual/core.html in the repository.

Registering a component

BUI.register(name, definition) registers a component from the core or from an Extension, without editing the core. It returns the factory function (see below) or null when the registration is invalid. Invalid registrations log an error and change nothing.

BUI.register('my-widget', {
    defaults: { size: 3, label: 'Widget', open: false, items: [] },
    variants: ['remote', 'multi-select'],       // optional
    create(element, options, context) {
        const onClick = () => context.trigger('click-count', { size: options.size });
        element.addEventListener('click', onClick);
        return {
            update(next) { /* ... */ },
            destroy() { element.removeEventListener('click', onClick); }
        };
    }
});

Name rules

The name is kebab-case: lower-case letters, digits and hyphens, starting with a letter (date-picker). The name is used for the attribute data-bui-date-picker, the DOM events bui:date-picker:* and the factory BUI.datePicker. A name that is already registered, or that equals a core member such as init or dom, is rejected.

Definition

Definition properties
PropertyTypeRequiredDescription
createfunctionyescreate(element, options, context). Must return an instance object with a destroy() method.

A default option may not use a name whose attribute is reserved: theme, mode, i18n and i18n-attr, or the component name itself.

The create function

Arguments of create()
ArgumentDescription
elementThe target element.
optionsThe resolved options object. It is a fresh object for this instance, so the component may change it.

If create() throws, or returns something without a destroy() function, the core logs an error, stores nothing and the factory returns null. One broken element never stops the initialization of the others.

The core wraps instance.destroy(). Calling it directly removes the instance from the registry before your code runs, and a second call does nothing. If the instance object is frozen the wrapping is not possible: a warning is logged and the instance is cleaned up only by BUI.destroy().

Initialization from HTML

Put data-bui-{name} on the element. BUI.init() finds it. The attribute value selects a variant when the component declares any; an empty value means no variant. An unknown variant logs a warning and no variant is used.

<div data-bui-my-widget></div>
<div data-bui-my-widget="remote" data-bui-per-page="25" data-bui-open data-bui-items='["a","b"]'></div>

Options are read from data-bui-{option-in-kebab-case}, and only for options that exist in defaults. The default value decides how the text is converted:

Attribute conversion

An invalid attribute value logs a warning and the default is used.

Initialization from JavaScript

Registering a component creates a factory on the namespace: BUI.myWidget(target, options). target is an element or a selector (the first match is used). A target that does not exist logs a warning and returns null.

const widget = BUI.myWidget('#demo', { size: 9 });
const remote = BUI.myWidget.remote('#other', { open: true });   // variant factory
widget === BUI.myWidget('#demo');                                // true

Initialization is idempotent: calling a factory again on the same element and component returns the existing instance. Options passed the second time are ignored.

Option priority and validation

Priority from lowest to highest: defaults, HTML attributes, JS options. Plain objects merge deeply; arrays and other values replace. A JS option whose type differs from the default logs a warning and is dropped. An option that is not in defaults logs a warning but is still passed to create(). A default of null accepts any type.

Automatic init and BUI.init

BUI.init(root?) initializes every registered component found on root and inside it. root is an element, a selector, document or a fragment (default document). It returns an array of the instances it created; elements that were already initialized are skipped. Components are processed in registration order, then in document order.

With autoInit on (the default) the core calls BUI.init(document) on DOMContentLoaded. If the script is loaded after that point, the call runs in the next task, so BUI.config({ autoInit: false }) written right after the script tag still takes effect.

BUI.config({ autoInit: false });
// later, for example after inserting server-rendered HTML:
const created = BUI.init('#content');

Observer

With BUI.config({ observe: true }) the core watches the document with a MutationObserver and calls BUI.init(node) for every element that is added. It starts only after the document is ready and after the first automatic init. It is off by default.

Warning

The observer only initializes. Removing an element does not destroy its instance, because a removed element may be inserted again. Call BUI.destroy(element) or instance.destroy() before removing a component, or its listeners and timers stay alive.

Instances and destroy

Instance functions
FunctionDescription
BUI.getInstance(target, name)Returns the instance of component name on the element, or null. An unknown component name or a missing element logs a warning.
BUI.destroy(root?)Calls destroy() on every instance on root and inside it, and returns how many. With no argument it covers instances on elements that are in the document.
BUI.destroyAll()Destroys every instance, including those on elements that are not in the document. Returns the count.

Instances are stored in a WeakMap keyed by element. The core keeps only weak references to enumerate them, so an element that is dropped without being destroyed can still be garbage collected.

Examples

Note

The core ships no component. The examples use my-widget as a placeholder name for a component that you register yourself. The snippets are not live demos. A runnable check of every behavior described here is tests/manual/core.html in the repository.

Reading and replacing an instance

const first = BUI.getInstance('#demo', 'my-widget');
first.destroy();                              // removes it from the registry
const second = BUI.myWidget('#demo');         // a new instance
first === second;                             // false

Listening for registrations

const stop = BUI.on('init', ({ root, count }) => console.log(count, 'created on', root));
BUI.init(document.body);
stop();

Writing a component that cleans up

BUI.register('my-widget', {
    create(element, options, context) {
        const onResize = BUI.utils.debounce(() => { /* ... */ }, 100);
        window.addEventListener('resize', onResize);
        return {
            destroy() {
                window.removeEventListener('resize', onResize);
                onResize.cancel();
            }
        };
    }
});

Responsive behavior

Initialization does not depend on the viewport width. Components that change behavior by breakpoint use matchMedia and must remove the listener in destroy().

Accessibility

The core does not add roles, labels or focus handling. A component adds its ARIA attributes while mounting, inside create(), and removes them in destroy() so the element returns to its original state. When an initialization fails the element is left untouched and remains usable as plain HTML.
