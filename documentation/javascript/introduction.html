Introduction

The BUI namespace: registry, init, events, helpers and logger, with no build step.

Overview

The core script assets/js/baset-ui.js creates one global, window.BUI. It gives components a shared base: a registry, automatic and manual initialization, instance tracking, an options parser, DOM events, small helpers and a logger. It needs no build step and has no dependencies.

The core contains no component and no Theme, Locale, Icon, Toast or Dialog system. Those arrive in later tasks and build on this page set.

Note

The script targets evergreen browsers. It uses WeakMap, WeakRef, MutationObserver and CustomEvent. It has been tested in Chromium only.

Installation and include

Load the Core stylesheet and then the Core script. Extensions, when they exist, load after the Core script.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<script src="assets/js/baset-ui.js"></script>

Place the script at the end of <body> or load it with defer. If the script is loaded twice, the second copy logs a warning and does nothing.

console.log(BUI.version); // "0.0.0-foundation"

Configuration

BUI.config(options) changes the global settings and returns a copy of the current settings. BUI.config() without arguments only reads them. Unknown keys, non-boolean values for the boolean keys and invalid log levels are rejected with a warning, and the current value is kept.

Global options
NameTypeDefaultDescription
autoInitbooleantrueRun BUI.init(document) once the document is ready.
observebooleanfalseInitialize elements added to the page later. See Initialization.
logLevelstring"warn"One of silent, error, warn, info, debug.
 
BUI.config({ autoInit: false });          // write it right after the script tag
BUI.config({ logLevel: 'debug' });
const settings = BUI.config();            // { autoInit, observe, logLevel }

Settings other than these three do not exist yet. Later systems (Theme, Locale) will add their own when they are implemented.

Examples

Note

The core ships no component. The examples use my-widget as a placeholder name for a component that you register yourself. The snippets are not live demos. A runnable check of every behavior described here is tests/manual/core.html in the repository.

The smallest complete flow: register a component, mark an element in HTML, and let the core initialize it.

<div id="demo" data-bui-my-widget data-bui-size="4"></div>

<script src="assets/js/baset-ui.js"></script>
<script>
    BUI.register('my-widget', {
        defaults: { size: 1 },
        create(element, options, context) {
            element.textContent = 'size ' + options.size;
            return { destroy() { element.textContent = ''; } };
        }
    });
</script>

Register before the document finishes loading so automatic init finds the element. Registering later works too: call BUI.init() afterwards.

Responsive behavior

The core has no layout and no behavior that depends on the viewport. A component that must react to width uses matchMedia and removes the listener in its destroy() (see RESPONSIVE_DESIGN.md).

Accessibility

The core adds no ARIA attributes, moves no focus and creates no visible elements. Keyboard support, ARIA and screen reader behavior are the job of each component and are documented on its page. Log messages go to the browser console only and are not announced to users.
