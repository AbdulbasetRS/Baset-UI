Breakpoints

Seven min-width breakpoints, designed Mobile First. Everything below 480px is the base design.

Introduction

Every responsive rule in Baset-UI is written Mobile First: the base styles target the smallest screens and min-width media queries add rules as the viewport grows. There are no max-width queries in the library.

Media queries cannot read CSS variables. The --bui-bp-* tokens exist for reading values (for example from JavaScript). In CSS, write the pixel value directly in the media query.

Usage

Write the base rule first, then widen with min-width. Use the same pixel values as the table above.

.my-panel { padding: var(--bui-space-3); }

@media (min-width: 768px) {   /* MD */
    .my-panel { padding: var(--bui-space-5); }
}

@media (min-width: 1200px) {  /* XL */
    .my-panel { padding: var(--bui-space-6); }
}

Reading a breakpoint in JavaScript

The token can be read with the standard DOM API. This is plain browser JavaScript, not a Baset-UI API. The read-out below uses this exact technique: 768px

var md = parseFloat(getComputedStyle(document.documentElement).getPropertyValue('--bui-bp-md'));
var isMdUp = window.matchMedia('(min-width: ' + md + 'px)').matches;

Responsive behavior

The base design applies below 480px. The breakpoint table is the only source of truth: a variant such as bui-grid-cols-md-2 has no effect below 768px, and the unprefixed class (if any) applies there.

RTL and LTR

Breakpoints are based on viewport width only, so they behave identically in both directions. Nothing in this system depends on dir.
