Dark Mode

Dark mode is a token set chosen by one attribute, on the page or on any element.

Overview

Dark mode is a set of token values selected by data-bui-mode="dark". Components and utilities read tokens, so nothing else changes. The attribute works on <html> or on any element, and the element paints its own background and text color, so a dark panel can sit inside a light page. Core also sets color-scheme to dark (or light) on the element, which makes native scrollbars and form controls follow.

Scoped dark mode

Both panels use the same markup; only data-bui-mode differs. The attribute is on the panel itself.

Switch at runtime

The buttons below use BUI.theme; the page changes immediately and the choice is saved. The Navbar Dark mode button does the same.

BUI.theme.setMode('dark');
BUI.theme.toggleMode();   // returns the new mode
BUI.theme.getMode();      // 'light' | 'dark'

The buttons are bui-docs-btn, a docs-only class: the library has no Button component yet.

Saved preference and system setting

On load, BUI.theme chooses the mode in this order:

  1. The mode saved in localStorage (bui-mode), written by setMode() or toggleMode().
  2. Otherwise the operating system setting, prefers-color-scheme.
  3. Without matchMedia, the data-bui-mode written in the markup, then light.

When the user has not chosen a mode, the page follows the operating system live: if the system switches between light and dark, the mode changes and bui:theme:change fires with source: "system". After an explicit choice the page stops following the system, even when saving failed.

Warning

The saved preference and the system setting both win over data-bui-mode written in the markup. That attribute is only the value before scripts run and the fallback without matchMedia. To start every visitor in dark mode, call BUI.theme.setMode("dark"); it is then saved like any other choice.

Avoid the flash of the wrong mode

Core runs at the end of the page, so a saved dark mode would first paint light. Put this small script in <head>, after the stylesheets and before <body>. It uses the same keys and rules as BUI.theme, and every storage access is guarded so it never throws.

<script>
    (function () {
        var d = document.documentElement, t = null, m = null;
        try { t = localStorage.getItem('bui-theme'); m = localStorage.getItem('bui-mode'); } catch (e) {}
        if (t && /^[a-z][a-z0-9]*(-[a-z0-9]+)*$/.test(t)) d.setAttribute('data-bui-theme', t);
        if (m !== 'light' && m !== 'dark') m = window.matchMedia && matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
        d.setAttribute('data-bui-mode', m);
    })();
</script>

This is the script used in the head of every page of this site (plus one extra line for the docs-only direction switcher). A saved theme other than default needs its stylesheet linked in the page, otherwise only the attribute is set.

When localStorage is unavailable (blocked, private mode, a sandboxed frame), reading and writing fail silently: nothing is thrown, the mode still changes for the current page, and only a debug message is logged. Nothing is saved for the next visit.

Accessibility

Light and Dark are both checked against the contrast table on the Colors page (40 pairs per mode), and the same method is applied to Ocean on the Themes page. color-scheme keeps native controls readable. Respecting prefers-color-scheme serves users who set a system-wide preference. The Navbar mode button is a toggle button with aria-pressed. Screen reader behavior was not tested.
