Themes

A theme is a CSS file that redefines tokens. Core is never edited.

Overview

A theme is a CSS file that redefines design tokens. It never edits baset-ui.css and never targets a component, so it controls every component through the tokens they read. Two attributes on <html> (or on any element) choose the look: data-bui-theme (default default) and data-bui-mode (light or dark).

The library ships one extra theme, ocean, in assets/css/themes/ocean.css. It changes colors, the font family, the radius scale, shadows, the thick border width and the focus ring width, in both modes. Use the Theme select in the Navbar to switch the whole documentation site to it.

Note

No component is implemented yet. The examples below show the tokens through base elements, utilities and docs-only demo boxes. Components will pick the theme up through the same tokens when they exist.

Include and activate

Load the theme after Core. The file only declares tokens, so it is safe to load even when the theme is not active.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/themes/ocean.css">

<html lang="en" dir="ltr" data-bui-theme="ocean" data-bui-mode="light">

Or switch at runtime with BUI.theme (no reload; the choice is saved):

BUI.theme.set('ocean');
BUI.theme.get();          // 'ocean'
BUI.theme.set('default');

Add the small <head> script from the Dark Mode page so a saved theme and mode are applied before the first paint.

Warning

Core declares the static tokens (font family, radius, border widths, focus ring) on :root only. A nested scope that sets a theme overrides the tokens that theme defines, but a nested default scope cannot reset what an ancestor theme changed. While the page itself uses Ocean, the Default panel therefore keeps the Ocean font, radius and border width; its colors and shadows still switch. This is a property of the Task 03 token scopes, not of the theme file.

Create a theme

  1. Create assets/css/themes/{name}.css.
  2. Define the Light tokens under [data-bui-theme="{name}"]. Do not use :root, so the theme works on any element.
  3. Define the Dark tokens under [data-bui-theme="{name}"][data-bui-mode="dark"]. Repeat every mode-dependent token of the Light block, otherwise a Light value leaks into Dark.
  4. Do not use !important or component selectors.
  5. Check the contrast (table above is the method) and try every registered component.
  6. Link the file after baset-ui.css and activate it with data-bui-theme or BUI.theme.set().
  7. Add it to the Theme list of the Navbar select if you want the documentation to offer it (THEMES in documentation/assets/js/docs.js).
/* assets/css/themes/sunset.css */
[data-bui-theme="sunset"] {
    --bui-color-primary: #b3470d;
    --bui-color-primary-hover: #8f3a0b;
    --bui-color-primary-active: #6f2d08;
    --bui-color-primary-contrast: #ffffff;
    --bui-radius-md: 0.25rem;
}
[data-bui-theme="sunset"][data-bui-mode="dark"] {
    --bui-color-primary: #ff9f66;
    --bui-color-primary-hover: #ffb286;
    --bui-color-primary-active: #ffc7a6;
    --bui-color-primary-contrast: #1c1006;
}

Which tokens exist is documented on the CSS Variables page. A theme may leave a token alone: Ocean does not redefine success, warning, danger and info.

Replace the Default theme

There are two ways. The first is recommended: it does not edit the meaning of default.

  1. Ship your own theme and make it the active one. Create brand.css as above and set data-bui-theme="brand" on <html> (or call BUI.theme.set('brand') once at startup).
  2. Redefine default. Load a file after Core that targets [data-bui-theme="default"] with the same two blocks (Light, and Dark with both attributes on the same element). The <html> element keeps data-bui-theme="default", so every page picks the new values up without changing markup.
[data-bui-theme="default"] {
    --bui-color-primary: #7a1fa2;
    --bui-color-primary-hover: #63198a;
    --bui-color-primary-active: #4e1470;
    --bui-color-primary-contrast: #ffffff;
}
[data-bui-theme="default"][data-bui-mode="dark"] {
    --bui-color-primary: #d79bf0;
    --bui-color-primary-hover: #e3b4f5;
    --bui-color-primary-active: #ecc9f8;
    --bui-color-primary-contrast: #1d0a27;
}

Core still declares Light values on :root with a lower specificity, so the file above wins without !important as long as it is loaded after baset-ui.css.

Load a theme dynamically

When you do not want to link every theme up front, BUI.theme.load(name, url) adds the stylesheet on demand and returns a Promise. It does not activate the theme.

await BUI.theme.load('ocean', 'assets/css/themes/ocean.css');
BUI.theme.set('ocean');

If the same stylesheet is already linked in the page, load() reuses it and does not add a second link. A saved theme that is not linked yet would be applied without styles, so link themes that users can save (as this site does) or load them before the first paint.

JavaScript API

BUI.theme is part of the Core script. Modes are covered on the Dark Mode page.

Try it

These buttons call BUI.theme, so they change the whole page and the choice is saved, exactly like the Navbar controls. data-docs-readout shows the current state.

document.querySelectorAll('[data-theme-set]').forEach((button) => {
    button.addEventListener('click', () => BUI.theme.set(button.dataset.themeSet));
});

The buttons are bui-docs-btn, a docs-only class: the library has no Button component yet.

Accessibility

A theme changes colors only through tokens, so the contrast table above is the check to repeat for every new theme (Light and Dark). Focus rings use --bui-color-focus and --bui-focus-ring-width; Ocean widens the ring to 3px. Changing the theme does not move focus and announces nothing. Screen reader behavior of the switcher controls was not tested.
