Icons

Six weights, one class per icon, colored by the text color and mirrored on request in RTL.

Overview

An icon is an empty <i> element with two classes: a weight (bui-icon-{weight}) and a name (bui-icon-{name}). The artwork is an SVG used as a CSS mask over the element, and the element paints the mask with currentColor, so an icon takes the text color and the font size of its context. There is no JavaScript and no icon font.

The initial set has icons, each in six weights: thin, light, regular, solid, bold and duotone. When the weight class is left out, the weight is light. The artwork comes from Phosphor Icons (MIT License, see License).

Note

The catalog below is built with library components: the details panel is a Dialog (BUI.dialog), and its buttons, text fields, checkboxes and radios are Button, Input, Checkbox and Radio. The two drop-downs still use a native <select> styled by the documentation site (bui-docs-select), because the library has no Select component yet.

Catalog

Search by name or keyword, filter by category, and choose the weight shown in the grid. Select an icon to open its details: all six weights, size, color, ready-to-copy HTML and the class names.

    Installation and include

    Icons are an Extension (CSS only): a single file loaded after baset-ui.css. It needs no JavaScript and registers nothing with BUI.register. The file is generated from the SVGs in assets/icons/ and embeds them as data: URIs, so it makes no further requests.

    <link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">
<!-- optional theme after them -->

<i class="bui-icon-light bui-icon-x" aria-hidden="true"></i>

    Note

    CORE_ASSETS.md makes a component an Extension when two of its criteria hold. Icons meet two: the stylesheet is far above the 15KB guideline (see Size) and most pages do not need it.

    solid is the Phosphor "fill" artwork. duotone needs no second layer: the artwork has a background shape at 20% opacity, and the mask keeps that alpha, so the shape is drawn at 20% of the current color and the outline at full color.

    RTL and directional icons

    Icons that point in a direction must mirror in RTL, and icons that do not (a clock, a logo) must not. Add bui-icon-flip-rtl to a directional icon: it applies transform: scaleX(-1) when the computed direction is RTL (the :dir(rtl) pseudo-class, as in the Position utilities). The class is never added automatically, because the same artwork can be literal (an arrow that points at something on the screen) or semantic (a "next" arrow). The catalog marks the directional icons and adds the class to their generated code.

      Adding an icon

      The generator is tools/build-icons.js: plain Node, no dependencies. It reads the manifest and the SVGs and writes the stylesheet and the catalog data. A new icon needs all six weights, or the generator fails and names the missing file.

      1. Put one SVG per weight in assets/icons/{weight}/{name}.svg (thin, light, regular, solid, bold, duotone). The name is kebab-case, describes the meaning, and cannot be a weight, a size or flip-rtl. Each SVG needs xmlns and viewBox, and no scripts, links or embedded images.
      2. Add an entry to assets/icons/icons.json: name, directional (true when it must mirror in RTL), and optionally categories and tags for the catalog search.
      3. Run the generator, then check that the files are current.
      4. If the artwork is not from Phosphor, add its license to THIRD_PARTY.md.
      5. Check the new icon in the catalog (all weights, RTL, Light and Dark), and update CHANGELOG.md.
      node tools/build-icons.js
node tools/build-icons.js --check

      The generated files are assets/css/extensions/baset-ui-icons.css and documentation/assets/js/icons-data.js. Do not edit them by hand.

      The cost grows with the number of icons (about 3 KB raw per icon, for all six weights), and every weight of every icon is in the file even when a page uses one weight. A page that needs a handful of icons can build a smaller file from the same generator by editing the manifest, which is a decision for the project owner and not part of this task.

      Responsive behavior

      Icons do not change with the breakpoint. They scale with the font size (1em) or follow a size class, and they never take part in layout beyond their box (inline-block, flex-shrink: 0). The catalog grid adapts its column count to the width, and the details dialog fits a 320px viewport and scrolls inside itself.

      Accessibility

      Decorative icons

      An icon that repeats nearby text or adds only decoration gets aria-hidden="true". This is the default in every example.

      Icons that carry meaning

      An icon alone in a control needs a name on the control: the icon stays hidden. Do not rely on the icon alone in critical contexts (WCAG 1.4.1): add text. An informative icon outside a control uses role="img" and aria-label, with the label coming from your i18n texts.

      The button is a library Button with bui-btn--icon: the accessible name is on the button and the icon inside it is hidden.

      Keyboard

      The catalog items are buttons (Enter or Space opens the details). The details open in a BUI.dialog: focus moves to the selected weight, Tab and Shift+Tab stay inside the dialog, the arrow keys change the weight in the radio group (they follow the reading direction in RTL), Esc and the close button close it, and focus returns to the icon that opened it. Everything behind the dialog is inert while it is open.

      Contrast and forced colors

      An icon has the contrast of the text color it takes. A meaningful icon needs 3:1 against its background (WCAG 1.4.11). Because the icon is a painted background, a forced-colors mode would hide it, so the stylesheet repaints icons with CanvasText there. Printing keeps the color (print-color-adjust: exact).

      Screen reader

      The attributes above follow the documented behavior. Screen reader announcements were not tested with NVDA, JAWS or VoiceOver for this release.
