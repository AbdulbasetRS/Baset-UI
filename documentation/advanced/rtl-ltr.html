RTL & LTR

Logical properties make every layout and utility flip with the dir attribute.

Overview

Direction is set with the dir attribute on <html>, or on any container for a local preview. The library is written with logical properties (margin-inline-start, padding-inline, inset-inline-start, border-start-start-radius, text-align: start) and never with physical left/right, so Flex and Grid layouts and every utility flip by themselves. No row-reverse is used to fake a direction.

Switch the page direction

The RTL button in the Navbar sets dir on <html> and remembers it (docs-only key bui-docs-dir), so you can review any page in both directions. In your own site, set the attribute yourself or let BUI.locale do it: loading a locale sets dir and lang from its meta.direction.

document.documentElement.dir = 'rtl';
BUI.dom.isRTL();                 // true: reads the computed direction
BUI.locale.getDirection();       // direction of the active locale

The buttons are bui-docs-btn, a docs-only class: the library has no Button component yet. Unlike the Navbar button, these buttons do not save the choice.

Logical utilities

Use the logical names in markup. The physical equivalent shown for LTR is for orientation only; do not write it.

Logical utilities and what they mean
Utility familyExamplesLTR / RTL meaning
Marginbui-ms-*, bui-me-*start side / end side: left / right in LTR, right / left in RTL
Paddingbui-ps-*, bui-pe-*start / end padding
Borderbui-border-s, bui-border-estart / end border
Radiusbui-rounded-s-*, bui-rounded-e-*, bui-rounded-ss-*, bui-rounded-ee-*start / end side, or one logical corner
Positionbui-start-0, bui-end-0, bui-translate-middleinset on the start / end side; translate-middle flips its horizontal shift with :dir(rtl)
Flex and Gridbui-flex-row, bui-justify-startthe main axis follows the direction

The details of each family are on the Spacing, Borders and Position pages.

Rules for your own CSS

  • Write margin-inline-start, padding-inline, inset-inline-start, text-align: start, float: inline-start. A physical left/right needs a documented reason (for example a drawn shape that must not mirror).
  • Read the direction from document.documentElement.dir or BUI.dom.isRTL(element) and react when it changes.
  • Directional icons (arrows, previous and next) must mirror in RTL. The icon system is not implemented yet.
  • Horizontal arrow keys are reversed in RTL for composite widgets. No such component is implemented yet.
  • Test every component in both directions.

JavaScript API

Direction helpers
NameReturnsDescription
BUI.dom.isRTL(element?)booleanComputed direction of the element (default <html>). A detached element returns false.
BUI.locale.getDirection()"ltr" or "rtl"Direction of the active locale; before any locale is active, the current dir of <html>.

There is no event for a direct change of the dir attribute. Components that need to know observe the attribute (a MutationObserver on <html>), as the Navbar button of this site does. A locale change fires bui:locale:change.

Accessibility

lang and dir on <html> tell assistive technology which language and direction to use, which is why BUI.locale.use() updates both. Code blocks in this documentation stay left to right in RTL pages because code is not mirrored. Screen reader behavior in RTL was not tested.
