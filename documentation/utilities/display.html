Display

Control how an element is rendered, and change it at any breakpoint, with small independent classes.

Introduction

Display utilities set the CSS display property from HTML. Each class does one thing, so they combine with the Grid and Flexbox classes without extra CSS. Pattern: bui-d-{value}, and bui-d-{breakpoint}-{value} to apply a value from a breakpoint upward.

Classes

ClassCSSDescription
bui-d-nonedisplay: noneRemoves the element from the layout. It takes no space and is not exposed to assistive technology.
bui-d-inlinedisplay: inlineFlows with text. Width, height and block margins do not apply.
bui-d-inline-blockdisplay: inline-blockFlows with text, but accepts width, height and margins.
bui-d-blockdisplay: blockStarts on a new line and fills the available width.
bui-d-griddisplay: gridBlock level grid container. Gap and columns are not set: add bui-grid-cols-{n} and bui-gap-{k}, or use bui-grid which includes the default gap.
bui-d-inline-griddisplay: inline-gridGrid container that sits inline with text.
bui-d-flexdisplay: flexBlock level flex container. Direction, wrap and alignment come from the Flexbox classes.
bui-d-inline-flexdisplay: inline-flexFlex container that sits inline with text.

Responsive variants

Every value has a variant for each breakpoint: bui-d-{breakpoint}-{value}, for example bui-d-md-block or bui-d-xl-none. Breakpoints: xs, sm, md, lg, xl, xxl, xxxl. A variant applies from its breakpoint upward (Mobile First), so write the smallest-screen class first, then add the larger overrides.

How conflicts are resolved

All display classes (base and responsive) have the same specificity and no !important. When two of them apply at the same time, the one defined later in baset-ui.css wins. The responsive variants are defined after the base classes and in ascending breakpoint order, so a larger breakpoint always overrides a smaller one: bui-d-block bui-d-lg-none is a block below 992px and hidden from 992px.

Do not put two base classes on one element (for example bui-d-none bui-d-block). Which one wins depends on file order and is not a supported use. Use a base class plus responsive variants instead.

The hidden attribute always wins. Display classes do not match an element that has the hidden attribute, the same rule used by bui-flex and bui-grid. An element with hidden stays hidden even when it also has bui-d-flex. Remove the attribute to show it.

Responsive behavior

Display is the only utility group with breakpoint variants in this release. Variants exist for xs, sm, md, lg, xl, xxl, xxxl and apply from the breakpoint upward. Elements hidden with bui-d-none are removed from the layout, so a large hidden area never causes horizontal scrolling.

RTL and LTR

Display does not depend on direction: the same class gives the same result in both. Flex and Grid containers follow the page direction, so the first item is on the right in RTL.

Accessibility

bui-d-none (and a responsive variant that resolves to none) removes the element from the accessibility tree, so screen readers skip it and it cannot receive keyboard focus. Use it only for content that should be unavailable to everyone at that size. To hide content visually but keep it for screen readers, a visually hidden utility is needed; that is not part of this task. Do not use display to hide an element that must be announced, and do not rely on the visible order when you change display at breakpoints: the source order is what assistive technology follows.

Tokens used

None. Display classes set the display property directly. Breakpoint values are the pixel values from Breakpoints.
