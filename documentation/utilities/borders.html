Borders

Add borders and rounded corners from small classes that use the border, color and radius tokens.

Introduction

Border utilities are independent classes that you combine: a style class (or bui-border) draws the border, then optional width, color and radius classes change it. All values come from design tokens, so colors follow Light and Dark mode. Directional borders use logical properties and flip in RTL.

Width

bui-border-width-{n} sets the width of every side. The number is the pixel value of the matching token. A width class has no visible effect on a side that has no border style, so combine it with a style class or a directional class.

Color

bui-border-color-{name} sets the color of every side from the semantic tokens: default (--bui-color-border), and the roles primary, secondary, success, danger, warning and info (--bui-color-{role}). The tokens change with the mode, so the same class works in Light and Dark.

Directional borders

Directional classes draw one side with logical properties: block start, block end, inline start and inline end. Inline start is the left side in LTR and the right side in RTL, so the border follows the reading direction. Width and color classes apply to the whole element but only the side with a style is visible.

A directional border is always solid. Style classes such as bui-border-dashed draw all four sides, so do not combine a style class with a directional class on one element.

Combining utilities

Every class works alone or together with the others, in any order in the class attribute. The order that matters is the order of the rules in baset-ui.css: style, directional, width, color, radius, so a width or color class always overrides the default width and color of a style class, and radius is independent of all of them.

Responsive behavior

Border classes have no breakpoint variants in this release. Widths are fixed pixel tokens and radius uses rem, so they do not change with the viewport. Borders are part of the box (box-sizing: border-box is global), so adding one does not make a full width element wider than its container.

RTL and LTR

The directional classes use border-inline-start and border-inline-end (and the block versions), so they swap sides with dir. There are no left or right classes. Width, style, color and radius are symmetric and do not depend on direction.

Accessibility

A border is decoration. Do not use border color alone to carry meaning (error, success): add text or an icon, as with all color tokens. Border colors should keep a contrast of at least 3:1 against the background when the border is the only boundary of an interactive element such as an input. The default border color is subtle by design and does not meet this, so interactive components must use a stronger color. The warning color is a known exception in Light mode (see the note above).
