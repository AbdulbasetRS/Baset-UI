Overflow

Control what happens to content that does not fit, and truncate or clamp text.

Overview

Overflow utilities set overflow on both axes or on one axis, with a variant for every breakpoint. Two text helpers shorten long text: bui-text-truncate for one line and bui-line-clamp-{1..5} for several lines.

Note

All utilities use !important, the one place the library allows it (CORE_ASSETS.md). Truncate and line-clamp have no breakpoint variants.

Breakpoint variants: bui-overflow-md-auto, bui-overflow-x-lg-hidden, bui-overflow-y-xl-scroll and so on, for XS to XXXL. Setting one axis to visible while the other is not visible makes the browser compute visible as auto; that is standard CSS behavior.

Responsive behavior

Overflow classes without an infix apply at every width; with an infix they apply from that breakpoint upward and override the base class. A container that must not make the page scroll sideways at a 320px width should use bui-overflow-x-auto so wide content scrolls inside it (WCAG 1.4.10).

Accessibility

A region that scrolls must be reachable with the keyboard (WCAG 2.1.1). Browsers differ on whether a scroll container is focusable by default, so give it tabindex="0", a role="region" and an accessible name, as the examples above do. Do not put this on a container that has focusable children, because those already allow scrolling by focus. Truncated and clamped text loses content for everyone: the full text is still in the DOM and screen readers read it, but sighted users cannot, so do not truncate text they need to read to act, and show it fully elsewhere (for example in a dialog or detail view). The title attribute is not a reliable way to show it. Do not hide a scroll bar visually unless another way to scroll is clear.
