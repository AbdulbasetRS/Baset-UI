Visibility

Hide content visually, from everyone, or only until it receives focus.

Overview

There are three ways to hide an element, and they differ in who still gets the content. Pick by the audience, not by the look.

Hiding methods compared

Note

All utilities use !important, the one place the library allows it (CORE_ASSETS.md). There are no breakpoint variants: whether content is meaningful to assistive technology does not depend on the screen width.

Responsive behavior

These classes have no breakpoint variants. To show or hide content by width, use the Display utilities, and make sure the content hidden at one width is still reachable another way. bui-visually-hidden is positioned absolutely, so give a nearby ancestor bui-position-relative to keep the clipped box from affecting page scrolling in unusual layouts.

Accessibility

Use bui-visually-hidden for text that gives a control or a result its accessible name or context but would be redundant visually, such as the end of a link text or a label next to an icon. Do not hide meaningful content that sighted keyboard users need. Do not put bui-visually-hidden on an element that can receive focus unless it uses the focusable variant: a keyboard user would land on something they cannot see (WCAG 2.4.7). bui-invisible and bui-d-none remove the content for assistive technology as well, which is the right choice for content that is truly not relevant.

Screen reader testing

The accessibility behavior of these classes follows the documented behavior of the technique. It has not been verified with NVDA, JAWS or VoiceOver for this release.
