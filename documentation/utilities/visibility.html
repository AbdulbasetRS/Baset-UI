Visibility

Show or hide an element without changing the layout, and know how this differs from display none.

Introduction

Visibility utilities set the CSS visibility property. They change whether an element is drawn, not whether it takes space. Display utilities and visibility utilities are different tools: display: none removes an element from the layout, visibility: hidden keeps its space.

Classes

ClassCSSDescription
bui-visibility-visiblevisibility: visibleThe default. The element is drawn. A visible child inside a hidden parent is drawn again.
bui-visibility-hiddenvisibility: hiddenThe element is not drawn, but keeps its box and space in the layout. It is not exposed to assistive technology and cannot receive focus. Children inherit it unless they set visible.
bui-visibility-collapsevisibility: collapseFor table rows, row groups, columns and column groups: the row or column is removed and its space is given back to the table. On other elements the support differs between browsers (see below).

A visible child inside a hidden parent

Visibility is inherited, so a child can opt back in with bui-visibility-visible. This does not work with display: none.

Hidden parent text
This child is visible again
<div class="bui-visibility-hidden">
    Hidden parent text
    <div class="bui-visibility-visible">This child is visible again</div>
</div>

Collapse support. On table rows, row groups, columns and column groups, collapse is the intended use defined by the CSS specification and behaves as described above. On flex items, and on elements that are not part of a table, the behavior is not the same in every browser: it can act like hidden (space kept) or like removing the item. Do not use collapse outside tables unless you tested it in every browser you support. Use bui-d-none or bui-visibility-hidden instead. The table row example above was tested in Chromium only.

Responsive behavior

Visibility classes have no breakpoint variants in this release. To show or hide an element at a given breakpoint, use the responsive Display classes, for example bui-d-none bui-d-md-block. Because those remove the element from the layout, they never leave an empty gap.

RTL and LTR

Visibility does not depend on direction. A hidden element keeps its box, so the space it leaves is on the same side in RTL and LTR as the element itself would be.

Accessibility

visibility: hidden and collapse hide the element from screen readers and remove it from the keyboard order, the same as display: none. Do not use them for text that is only visually hidden but must still be announced; that needs a visually hidden technique, which is not part of this task. Use them for content that is really unavailable at that moment, for example a panel that is not open. Hidden content that is revealed later by script must also update the state that describes it (for example aria-expanded). This task adds no JavaScript.
