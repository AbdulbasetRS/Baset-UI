Position

Set the positioning scheme of an element, place it with logical offsets, and stack it with the z-index tokens.

Introduction

Position utilities have three parts: the position scheme (bui-position-{value}), the offsets (bui-inset-*) and the stacking order (bui-z-{level}). Offsets use logical properties, so an element placed at the inline start stays on the correct side in RTL and LTR. Position classes have no breakpoint variants in this release.

Position classes

ClassCSSDescription
bui-position-staticposition: staticThe default. In normal flow. Offsets and z-index have no effect.
bui-position-relativeposition: relativeIn normal flow, can be nudged with offsets, and becomes the reference box for absolute children.
bui-position-absoluteposition: absoluteRemoved from the flow and placed against the nearest positioned ancestor (any value except static).
bui-position-fixedposition: fixedRemoved from the flow and placed against the viewport, so it stays in place while the page scrolls.
bui-position-stickyposition: stickyIn normal flow until the offset is reached while scrolling, then it sticks. Needs an offset, for example bui-inset-block-start-0.

Inset classes

Pattern: bui-{property}-{step}. Steps map to the spacing tokens: 0 is --bui-space-0, 1 is --bui-space-1 (0.25rem), 2 is --bui-space-2 (0.5rem), 3 is --bui-space-3 (1rem). Offsets only work on an element that is not static.

ClassCSSDescription
bui-inset-{0-3}insetAll four sides
bui-inset-block-{0-3}inset-blockBlock start and block end (top and bottom in horizontal writing)
bui-inset-inline-{0-3}inset-inlineInline start and inline end (left and right in LTR, flipped in RTL)
bui-inset-block-start-{0-3}inset-block-startBlock start side only
bui-inset-block-end-{0-3}inset-block-endBlock end side only
bui-inset-inline-start-{0-3}inset-inline-startInline start side only
bui-inset-inline-end-{0-3}inset-inline-endInline end side only

The shorthand classes are defined before the single-side classes, so bui-inset-0 bui-inset-block-start-3 gives 0 on three sides and 1rem on the block start side.

Choosing a position

ValueTakes space in the flowPlaced againstScrolls with the page
staticYesNormal flowYes
relativeYes (at its original place)Its own original placeYes
absoluteNoNearest positioned ancestor, or the page if noneWith that ancestor
fixedNoThe viewportNo
stickyYesIts nearest scroll container, after it reaches the offsetUntil it sticks

Parents and scroll containers matter. An absolute element is placed against the nearest ancestor that is not static, so add bui-position-relative to the parent you want as the reference. A sticky element sticks inside its nearest scrolling ancestor (any ancestor with overflow other than visible, see Overflow) and never leaves its parent box. If an ancestor has overflow: hidden but does not scroll, the sticky element never sticks. A fixed element is normally placed against the viewport, but an ancestor with transform, filter or perspective becomes its reference instead.

Responsive behavior

Position, inset and z-index classes have no breakpoint variants in this release; they apply at every width. Use them on elements whose size is limited (a badge, an overlay) so that offsets in rem never push content outside a 320px screen.

RTL and LTR

Inset classes use logical properties: bui-inset-inline-start-* is the left side in LTR and the right side in RTL, and the same for the end. No class named after a physical side exists. The reference box of an absolute element does not depend on direction.

Accessibility

Position changes where an element is drawn, not where it is in the reading and focus order, which follows the markup. Keep a moved element in a sensible place in the source. A sticky or fixed element can cover other content or the focused element: leave room for it, and make sure it does not hide focus. A scrollable container needs tabindex="0" and a label so that keyboard users can scroll it, as in the sticky example.
