Close Button

A square icon button that closes or dismisses something. CSS only, with an accessible name that can be translated.

01. Installation & Include

Close Button is part of the Core stylesheet, so assets/css/baset-ui.css is required. It draws the x icon from the icon system, so assets/css/extensions/baset-ui-icons.css is required too: without it the button is empty. Load assets/js/baset-ui.js only if you want the accessible name translated (see section 06). Order: Core, then Extension, then Theme.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<button type="button" class="bui-btn-close" aria-label="Close"
        data-bui-i18n-attr="aria-label:common.close">
    <i class="bui-icon-regular bui-icon-x" aria-hidden="true"></i>
</button>

02. Customize

Every option below is a real class or attribute documented in section 04.

03. Default

The button has the static English name Close, so it is accessible without any JavaScript. data-bui-i18n-attr replaces it with the translation of common.close when the Locale Manager is used.

Component tokens

The tokens are declared on :root, on any [data-bui-mode] and on any [data-bui-theme] element. Close Button is designed to sit inside other components, so a parent can re-declare the color tokens on itself (for example --bui-btn-close-color: currentColor) without any selector for the close button. Names that contain _ are internal and not part of the API.

06. JavaScript API

CSS only, no JavaScript API. Close Button registers nothing with BUI.register and fires no events: what happens when it is pressed is up to the component that contains it or to your own click handler.

Translation is the only optional link to the JavaScript Core. CSS alone cannot translate an aria-label, so the markup carries a static English aria-label (works with no JavaScript) and the attribute data-bui-i18n-attr="aria-label:common.close". When baset-ui.js is loaded and BUI.locale.use() has run, the Locale Manager replaces the name with the translation and keeps it updated when the language changes. The key common.close already exists in every language file, so no i18n key was added for this component.

07. Responsive Behavior

Close Button has no breakpoint-specific styles. It is a fixed square that does not shrink in a flex row.

  • On touch devices (pointer: coarse) the square grows to 36px (sm), 44px (md) and 48px (lg). The small size on touch is below the 44px recommendation and above the 24px WCAG 2.2 AA minimum. The visible area of the button grows, not only the icon.
  • Hover styles apply only when the device can hover.
  • In a right-to-left page nothing mirrors: the x icon is symmetric. The button moves to the other end of a header through justify-content and logical margins such as bui-ms-auto.

08. Accessibility

Keyboard

It is a native <button>: Tab focuses it, Enter and Space activate it. A disabled button is not focusable. Pressing Escape is not handled here; closing on Escape belongs to the component that is closed.

ARIA

  • The button must have an accessible name, because it contains only an icon: aria-label on the button. The icon inside has aria-hidden="true".
  • Use type="button" so it never submits a form by accident.
  • When the context matters (several close buttons on a page), use a specific name such as "Close filters". The default common.close text is generic.
  • Meaning does not depend on color alone: the x shape carries it.

Screen reader

Not tested with a screen reader. Whether the translated name is announced in the right language after a language switch was not verified with assistive technology; the attribute value was verified in the browser.

Contrast and motion

Measured in Chromium in Light and Dark with the default and ocean themes, for the three sizes at rest, hover, active and focus-visible (48 samples). The icon contrast against its background is at least 5.90:1 at rest, 12.28:1 on hover and 9.96:1 when pressed (3:1 is required for an icon that carries meaning). The focus ring is at least 6.01:1 against the page. A disabled button is exempt from the contrast requirement. With prefers-reduced-motion: reduce the color transition is shortened by the duration tokens. Forced colors mode was only checked with the Chromium emulation (the transparent border stays drawn), not on a real Windows high contrast theme.
