Select

A custom combobox built over the native select: single and multiple choice, search, clear, option groups, validation states and a remote mode that loads the options from a URL. The native select stays in the page, so forms keep working.

01. Installation & Include

Select is part of the Core, so assets/css/baset-ui.css and assets/js/baset-ui.js are required. It does not need the icon Extension (its chevron, clear, remove and selected marks are drawn by CSS). Write a normal <select> with a label and add data-bui-select; BUI.init() runs on page load and enhances it.

<link rel="stylesheet" href="assets/css/baset-ui.css">

<label class="bui-form-label" for="fruit">Fruit</label>
<select id="fruit" name="fruit" data-bui-select>
    <option value="">Choose a fruit</option>
    <option value="apple">Apple</option>
    <option value="banana">Banana</option>
</select>

<script src="assets/js/baset-ui.js"></script>

Note

Without JavaScript the page keeps working with the native select. A select needs an accessible name: a <label for>, aria-label or aria-labelledby (the script warns in the Console when there is none).

Size decision (Core, not an Extension). Select adds about 65 KB of JavaScript and 17 KB of CSS before compression (12.5 KB and 2.5 KB gzip), which is over the 15 KB guideline, but it is used by most forms, and it uses the internal floating layer of the Core (the same one as Popover and Menu), so it could not live in an Extension without exporting that layer.

02. Customize

Every option is a real option or attribute documented in sections 04 and 06. Multiple is the native multiple attribute. Remote uses the countries fixture of this documentation site (see the fixture note in the Examples section): the Code Output shows the URL api/countries, which only works here because this page answers it. Per page and Load more apply to the remote mode only. Press the control or open it with the keyboard to see the list.

A single select with a placeholder. The sample options are declared text, not real data.

The native element is the source of truth

The control reads and writes the native <select>: name, required, form, FormData, Submit and Reset all work as they do without the script. The control also follows later changes to the native element: its disabled state, the is-valid / is-invalid classes, aria-invalid, required, its options (static mode) and its selection (after a change event, or when the form is reset). Setting select.value from a script does not fire an event by itself (a browser rule): dispatch change or call refresh().

05. Examples

Fixtures declared on this page

Sample options (fruits, sizes) are declared text. The remote examples read documentation/assets/data/select-countries.json (250 countries: ISO code and English name, generated from Intl.DisplayNames). var form = document.getElementById('ex-form');
var select = document.getElementById('ex-req');
form.addEventListener('submit', function (e) {
    e.preventDefault();
    var ok = select.checkValidity();
    select.classList.toggle('is-invalid', !ok);
    select.classList.toggle('is-valid', ok);
    select.setAttribute('aria-invalid', ok ? 'false' : 'true');
    if (!ok) { BUI.getInstance(select, 'select').open(); }
});
select.addEventListener('change', function () { select.classList.remove('is-invalid'); select.setAttribute('aria-invalid', 'false'); });

The page loads on first open (20 per page), loads the next page as you scroll, and asks again (after 300 ms) when you type. A previous request is cancelled when you type again. The chosen option is written into the native select, so it is submitted even when it is not on the loaded page.

Remote: slow network, error and empty

These switches control the fixture script of this page. Open the select below after changing them: a slow answer shows Loading, a failure shows the message with Retry (Enter retries from the keyboard), and the empty answer shows No results.

06. JavaScript API

Select is initialized from HTML (data-bui-select) by BUI.init(), or from JavaScript:

var select = BUI.select('#fruit', { searchable: true, clearable: true });
var remote = BUI.select.remote('#country', { url: 'api/countries', perPage: 20 });

select.setValue('banana');
select.getValue();            // "banana"
document.getElementById('fruit').addEventListener('bui:select:change', function (e) {
    console.log(e.detail.value, e.detail.source);
});

The events are fired on the native <select> and bubble. Methods that do not return a value return the instance, so they chain.

Remote mode

The request is a GET to url (an existing query string is kept) with the parameters below, made with the browser fetch and the headers Accept: application/json. Cross-origin URLs need the server to allow CORS. The select asks for page 1 on the first opening and again for each next page and for each search. A request that is no longer needed is cancelled (AbortController) and a late answer is ignored.

Remote request parameters
ParameterValue
pageThe page number, starting at 1.
perPageThe perPage option.
searchThe typed text, trimmed. Left out when it is empty.

The response must be JSON with this shape (group and disabled are optional):

{
    "items": [
        { "value": "EG", "label": "Egypt" },
        { "value": "FR", "label": "France", "disabled": false }
    ],
    "total": 250
}

More pages are requested while the number of loaded items is below total. When total is missing, a page that has as many items as perPage means there may be more. A repeated value is ignored. A failed request (network error, status other than 2xx, or an invalid body) shows the error message with a Retry button, and a failed or empty result is asked again at the next opening. The loaded list is kept between openings while a search is not active.

Warning

Option labels are always inserted as text, never as HTML. Validate on the server: the client only sends what the user chose.

07. Responsive Behavior

The control fills its container (inline-size: 100%) and a long label is cut with an ellipsis; the tags of a multiple select wrap onto more lines. The list is as wide as the control at least, as wide as its longest option at most, and never wider than the space left on the screen; it is as tall as the screen allows (maximum five and a half rows by default) and scrolls inside. It flips above the control when there is no room below. On a touch screen (coarse pointer) the control and the options are at least 44px high and the tag and clear buttons are larger.

Note

The list is placed by the page size, not by the width of the Playground preview, so the preview width buttons do not change where it flips.

08. Accessibility

Keyboard

Select keyboard

Arrow Down / Arrow UpOpens the list. When open, moves to the next or previous enabled option (it stops at the ends). In the remote mode, reaching the end loads the next page.
Home / EndFirst or last option (a select without search; in the search box they move the caret).

EnterOpens the list. When open, chooses the active option (and in the remote error state, retries). In a searchable select Enter with the list closed keeps its normal form behavior.

EscCloses the list and returns to the chosen value (a Dialog behind it stays open).
LettersA select without search: type to jump to the next option that starts with them. A select with search: the letters filter.
Backspace / DeleteMultiple: Backspace removes the last tag (with an empty search box). Single and clearable: clears the choice (with an empty or unedited search box).

The arrow keys are vertical, so they do not change in RTL.

ARIA

The control is a combobox (role="combobox", aria-haspopup="listbox", aria-expanded, aria-controls) with aria-activedescendant pointing to the active option, so the focus stays on the control. A searchable select makes the input the combobox (aria-autocomplete="list"); a select without search makes the value area the combobox. The list is role="listbox" (aria-multiselectable for multiple) with role="option" items (aria-selected, aria-disabled, and aria-setsize / aria-posinset because the list is rendered in chunks) and role="group" for groups. The name comes from the native select labels (aria-labelledby), aria-describedby, aria-required and aria-invalid are copied from the native element. The native select is hidden from assistive technology (aria-hidden, tabindex="-1") but not removed, so a browser validation message still points at the control and a failed validation moves the focus to it.

Screen reader

A polite status region announces the number of results while searching, the loading state, errors, and each choice and removal. The tags and the clear button also have names (translated with BUI.locale). Not tested with a screen reader in this release: the behavior of the status announcements and of aria-activedescendant in NVDA, JAWS and VoiceOver is unverified.

Known limits

The remove buttons on the tags of a select without search are mouse and touch only (hidden from assistive technology on purpose, because they sit inside the combobox); use Backspace with the keyboard. The clear button is also outside the Tab order for the same reason; use Backspace or Delete. The option list is rendered 100 at a time as you scroll or move, so very long lists open quickly, but a list of tens of thousands of options is not virtualized (a planned improvement for a later task).
