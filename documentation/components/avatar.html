Avatar

A person or entity shown as initials, an icon or an image, in five sizes and three shapes, with a status indicator and an overlapping group. The image fallback is a small JavaScript component.

01. Installation & Include

Avatar is part of the Core stylesheet. The image fallback needs the Core JavaScript (assets/js/baset-ui.js), because CSS cannot detect that an image failed to load. Without the script an avatar with initials, an icon or a working image still renders; only the fallback and its event are missing. Load the icons Extension only if you use an icon.

02. Customize

Every option is a real class or attribute documented in section 04. The names and initials are sample text. The image options use generated images declared as docs fixtures: a small drawing for "Image", and an intentionally broken data URI for "Image that fails to load", so you can watch the fallback with no network request. The status option adds the indicator to a single avatar; the group option shows three avatars and a counter at the chosen size and shape.

03. Default

SA 
<span class="bui-avatar" role="img" aria-label="Sara Ahmed"><span class="bui-avatar__text" aria-hidden="true">SA</span></span>

With no modifier, .bui-avatar is a medium circle. The name is on the avatar, as an accessible name for the initials, which are hidden from assistive technology so they are not read letter by letter.

Each avatar after the first uses a negative margin-inline-start equal to --bui-avatar-group-overlap times its own size, so the row overlaps correctly in left-to-right and right-to-left pages, and later avatars paint above earlier ones. Avatars in a group get the group size class (bui-avatar-group--lg) instead of each having its own. A "+3" counter is just an avatar with text; wrap a number in <bdi> so it keeps its order in right-to-left text. The group has role="group" and a label; the counter needs a label that says what it counts.

06. JavaScript API

Avatar registers an optional component, BUI.avatar. It only manages the image fallback: with no image, or with an image that always loads, you do not need it. Add data-bui-avatar to an avatar that contains an image and it starts automatically with BUI.init() (called on page load). To start it by hand use BUI.avatar(el).

What it does: it watches the image error and load events (and checks an image that already failed before the script ran), and adds or removes the state class .is-fallback. The state is a class because no standard attribute exists for it. While in fallback, the initials element (.bui-avatar__text) takes over the name that was in the image alt: it gets role="img" and aria-label with that text, and loses aria-hidden. When the image works again the original attributes are restored.

Decision

The fallback is a small JavaScript component and not CSS, because CSS has no selector for a failed image load. Everything else in Avatar (size, shape, status, group) is CSS only.

07. Responsive Behavior

Avatar has fixed sizes from tokens, so it does not change at breakpoints; it keeps its size on every screen.

  • An avatar never shrinks (flex: none), so a flex row does not squash it into an oval.
  • Put avatars in a container with bui-flex-wrap if there can be many. An Avatar Group does not wrap: it is one overlapping row, so cap the number you show and add a "+N" counter.
  • Initials are not truncated; keep them to one or two letters.
  • The smallest size (xs) is not a touch target. If the avatar is clickable, put it inside a button or link of at least 44 by 44 pixels.

08. Accessibility

Keyboard

Avatar is not interactive and is not focusable. If it opens a profile, put it inside a <button> or <a>; the control then carries the focus and the label.

ARIA

  • Initials are not read well letter by letter. Give the avatar role="img" and aria-label with the person's name, and mark the initials aria-hidden="true".
  • An avatar next to the visible name is decorative: use aria-hidden="true" on it so the name is not read twice.
  • An image has an alt with the name. In fallback the script gives the initials that name, so the avatar keeps one accessible name.
  • An icon is decorative (aria-hidden="true"); the label goes on the avatar.
  • A status indicator has its own role="img" and label ("Online"). Color is not the only cue: each status has a different shape.
  • An Avatar Group has role="group" and an aria-label; a "+3" counter has a label such as "3 more".

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). The names come from standard roles and labels; their announcement was not verified.

Contrast and motion

Initials were measured in Chromium for every size and shape, in Light and Dark, with the default and ocean themes, in both directions (120 samples): the lowest is 8.06:1, above the 4.5:1 AA threshold. The status indicator measured at least 5.02:1 against its surroundings (288 samples), above the 3:1 non-text minimum. In forced-colors mode an avatar gets a visible border. Avatar has no animation.
