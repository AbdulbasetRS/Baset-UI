Dialog

A modal window that asks for attention. Built on the native dialog element, with a shared overlay manager for focus, Esc, nesting and the page scroll lock.

01. Installation & Include

Dialog is part of the Core files: assets/css/baset-ui.css for the look and assets/js/baset-ui.js for the behavior (opening, closing, focus, scroll lock). Without the script the <dialog> stays closed. The close button draws the x icon, so assets/css/extensions/baset-ui-icons.css is needed for the examples on this page (the component itself does not require it).

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<button type="button" class="bui-btn" data-bui-dialog-open="#my-dialog">Open</button>

<dialog class="bui-dialog" id="my-dialog" aria-labelledby="my-dialog-title" data-bui-dialog>
    <div class="bui-dialog__panel">
        <div class="bui-dialog__header">
            <h2 class="bui-dialog__title" id="my-dialog-title">Title</h2>
            <button type="button" class="bui-btn-close" data-bui-dismiss aria-label="Close"
                data-bui-i18n-attr="aria-label:common.close"><i class="bui-icon-regular bui-icon-x" aria-hidden="true"></i></button>
        </div>
        <div class="bui-dialog__body">Content.</div>
        <div class="bui-dialog__footer">
            <button type="button" class="bui-btn" data-bui-dismiss>Done</button>
        </div>
    </div>
</dialog>

<script src="assets/js/baset-ui.js"></script>

Note

It is built on the native <dialog> element opened with showModal(), so it needs a current evergreen browser. It was tested in Chromium only (not in Firefox or Safari). The decision and its trade-offs are in COMPONENT_DEVELOPMENT.md.

02. Customize

Every option below is a real class or attribute documented in section 04. The preview holds a button and the dialog; press the button to open it (the dialog covers the page, as it does for your visitors, and it follows the preview's Light/Dark and RTL/LTR switches). The Responsive Preview width only resizes the preview box: a dialog is sized against the browser window, so use the browser window or the fullscreen-until-* classes' breakpoints to check responsive behavior (see section 07).

03. Default

A top-aligned, medium-width dialog with a header, a body and a footer. The page behind is locked and inert; Esc, the close button and a click on the dark area close it.

Dialog title

Sample body text. Press Esc, the close button, or click outside to close.

04. Variants & Options

Structure

The <dialog> element is the full-screen dark area; its first child __panel is the visible box. __header, __body and __footer go inside the panel (all three optional), and the title is __title. Name the dialog with aria-labelledby (the title id) and, if useful, aria-describedby.

Dialog classes and attributes
Class or attributeApplies toDescription
bui-dialog<dialog>The dialog and its dark area. Required.
bui-dialog--sm|md|lg|xl<dialog>Maximum width: 21rem, 33rem (default), 51rem, 72rem. Never wider than the screen.
bui-dialog--centered<dialog>Centers the panel vertically. The default is top aligned.
bui-dialog--scrollable<dialog>Only the body scrolls; header and footer stay. Without it the whole dialog scrolls inside the dark area ("page" scroll).
bui-dialog--fullscreen<dialog>Always fills the screen.
bui-dialog--fullscreen-until-sm|md|lg|xl<dialog>Fills the screen below 576px, 768px, 992px or 1200px, and is a normal dialog from that width up (combine with a size class).
bui-dialog__panelfirst childThe visible box. Required, and it must be a direct child.
bui-dialog__header, __title, __body, __footerinside the panelOptional parts. The footer aligns its buttons to the end.
data-bui-dismissany control insideCloses the nearest dialog when clicked. The value must be empty (or dialog); another value, such as data-bui-dismiss="alert" on an Alert inside the dialog, belongs to another component and does not close the dialog.
data-bui-dialog-open="#id"a button or linkOpens the dialog with that id. Works for dialogs added later.
.is-closing, .is-static-bumpstate (set by the script)Do not set them yourself.

Dynamic content

The body can be filled when the dialog opens. A function (JavaScript only) or a same-origin address returns the content; while it loads the body shows a status line, and if it fails an error line is shown and the dialog reloads on the next open.

Function

Loaded content

Fallback markup, restored by destroy().

 
BUI.dialog('#ex-load', {
    load: function (body) {
        // Return a string (HTML, so only trusted content), a Node, or a Promise of either.
        return fetch('/fragments/profile.html').then(function (r) { return r.text(); });
    }
});
<!-- Same-origin address: the HTML is inserted into .bui-dialog__body on first open -->
<dialog class="bui-dialog" id="remote" aria-labelledby="remote-t" data-bui-dialog data-bui-url="fragments/profile.html"> ... </dialog>

Warning

Loaded content is inserted as HTML, so load only content you control. A url on another origin is refused. The live function example above simulates a slow request with a timer, because a real address needs a server.

Open from JavaScript

Opened from JavaScript

Opened by BUI.dialog('#ex-js').open().

 
var dialog = BUI.dialog('#my-dialog', { static: true });
dialog.open();                 // true, or false if beforeopen was canceled
dialog.close('done');          // returnValue "done"
dialog.toggle();
dialog.isOpen();
dialog.destroy();              // closes at once, removes listeners

06. JavaScript API

BUI.dialog(target, options) returns an instance (the same one if called again for the element). BUI.modal is an alias of the same function; events, the data-bui-dialog attribute and BUI.getInstance(el, 'dialog') always use the name dialog. The target must be a <dialog>; anything else logs an error and returns null.

Methods

Dialog methods
NameReturnsDescription
open(trigger?)booleanOpens the dialog. trigger (an element) is where focus returns. Returns false if it is already open or beforeopen was canceled.
close(returnValue?)booleanStarts closing (after the exit animation). Returns false if it is not open or beforeclose was canceled.
toggle()booleanOpens or closes.
isOpen()booleanWhether it is open.
destroy()voidCloses at once without animation or events, removes every listener and timer, restores the original body markup if content was loaded, and removes the tabindex it added to the panel.

Events

DOM events on the <dialog>, named bui:dialog:{name}. They bubble (a dialog nested in another dialog's markup also reaches the outer listeners, so compare event.target). detail.relatedTarget is the element that opened it.

Dialog events
EventCancelableDetailWhen
beforeopenyesrelatedTargetBefore opening. preventDefault() keeps it closed.
opennorelatedTargetRight after it opened (the entry animation may still run).
beforecloseyessource, relatedTargetBefore closing. source is api, dismiss, escape, backdrop or form. preventDefault() keeps it open.
closenosource, returnValue, relatedTargetAfter it closed and focus returned. Also fires if the native close() was called on the element.
loadno(empty)Dynamic content was inserted.
loaderrornoerrorDynamic content failed to load.

Note

Events are named beforeopen and beforeclose (no hyphen), like the platform's beforetoggle. A <form method="dialog"> submit is intercepted so it also goes through beforeclose. Calling the native dialog.close() directly skips beforeclose by design of the platform.

Overlay manager

Dialog and Drawer share one manager, BUI.overlay. It keeps the stack of open overlays and the single page scroll lock, and drops an open overlay that was removed from the page.

BUI.overlay
NameReturnsDescription
getStack()array of elementsThe open dialogs and drawers, bottom first.
getTop()element or nullThe top one.
closeAll()numberAsks every open overlay to close, top first, and returns how many accepted.

While a dialog or drawer is open, the Toast region moves inside the topmost one (a modal dialog makes everything outside it inert, so toasts outside it could not be focused or clicked) and returns to <body> when none is open.

While an overlay is open the page gets overflow: hidden and the custom property --bui-scroll-lock-gap (the scrollbar width) on <html>. Where the browser supports scrollbar-gutter the scrollbar space is kept reserved so nothing moves, and the dark area stops short of that strip (the page color shows there). Elsewhere padding of the same width is added to <html>.

07. Responsive Behavior

The panel is as wide as its size class allows but never wider than the screen minus a 1rem margin, so it fits from 320px. Long content scrolls: the whole dialog by default, or only the body with bui-dialog--scrollable. Use bui-dialog--fullscreen-until-md (or sm, lg, xl) to give small screens the whole screen; these classes are Mobile First (fullscreen is the base and a min-width query ends it). A dialog is positioned against the browser window, not against its parent, so it does not respond to the width of a container.

08. Accessibility

Keyboard

Dialog keyboard
KeyAction
Tab / Shift+TabMoves between the focusable elements inside. At the last or first one it wraps, so focus never leaves the dialog. The page behind cannot be reached.
EscCloses the top dialog only (not the ones below it). Off with keyboard: false.
Enter / SpaceActivates the focused button, including the close button.

Focus

On open, focus goes to the focus option's element, else to the first focusable element, else to the panel itself. On close it returns to the element that opened the dialog (the trigger, or whatever was focused when open() was called without one). Browsers such as Safari do not focus a button when it is clicked, which is why the trigger is remembered.

ARIA and screen readers

The native element provides role="dialog" and modality: everything outside is inert and hidden from assistive technology while it is open. You provide the name: aria-labelledby pointing at the title (or aria-label), and aria-describedby for a short description. For a dialog that needs an immediate response, such as a confirmation, add role="alertdialog". A warning is logged on creation if the dialog has no accessible name. The close button's name comes from the language files (common.close).

Not tested with a screen reader (NVDA, VoiceOver, JAWS). The behavior above is the platform's and was verified in Chromium only; see the test report in CHANGELOG.md.

Motion, colors and touch

The enter and exit animations use the motion tokens, so prefers-reduced-motion removes them. In forced colors mode the dark area is dropped and the panel keeps a system-color border. The panel text uses the same tokens as the rest of the library, in every theme, in Light and Dark.
