Drawer

A panel that slides in from one edge of the screen. Same behavior as Dialog: focus, Esc, nesting and the page scroll lock come from the shared overlay manager.

01. Installation & Include

Drawer is part of the Core files: assets/css/baset-ui.css for the look and assets/js/baset-ui.js for the behavior (opening, closing, focus, scroll lock). Without the script the <dialog> stays closed. The close button draws the x icon, so assets/css/extensions/baset-ui-icons.css is needed for the examples on this page (the component itself does not require it).

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<button type="button" class="bui-btn" data-bui-drawer-open="#my-drawer">Open</button>

<dialog class="bui-drawer bui-drawer--end" id="my-drawer" aria-labelledby="my-drawer-title" data-bui-drawer>
    <div class="bui-drawer__panel">
        <div class="bui-drawer__header">
            <h2 class="bui-drawer__title" id="my-drawer-title">Title</h2>
            <button type="button" class="bui-btn-close" data-bui-dismiss aria-label="Close"
                data-bui-i18n-attr="aria-label:common.close"><i class="bui-icon-regular bui-icon-x" aria-hidden="true"></i></button>
        </div>
        <div class="bui-drawer__body">Content.</div>
    </div>
</dialog>

<script src="assets/js/baset-ui.js"></script>

Note

It is built on the native <dialog> element opened with showModal(), so it needs a current evergreen browser. It was tested in Chromium only (not in Firefox or Safari). The decision and its trade-offs are in COMPONENT_DEVELOPMENT.md.

02. Customize

Every option below is a real class or attribute documented in section 04. The preview holds a button and the drawer; press the button to open it (the drawer slides in over the page, as it does for your visitors, and follows the preview's Light/Dark and RTL/LTR switches). Try Start and End with the RTL switch: they swap sides. The Responsive Preview width only resizes the preview box, since a drawer is sized against the browser window.

03. Default

A drawer that slides in from the start edge (the left in LTR, the right in RTL), medium size, with a header and a body. The page behind is locked and inert, exactly as for a Dialog.

Drawer title

Sample body text. Press Esc, the close button, or click outside to close.

04. Variants & Options

Structure

Like a Dialog, the <dialog> is the full-screen dark area and its first child __panel is the visible box, with optional __header, __title, __body and __footer. The body scrolls when the content is long; the header and footer stay.

Drawer classes and attributes
Class or attributeApplies toDescription
bui-drawer<dialog>The drawer and its dark area. Required.
bui-drawer--start (default), --end<dialog>Side edges. They follow the writing direction: start is the left in LTR and the right in RTL. The slide direction follows too.
bui-drawer--top, --bottom<dialog>Top or bottom edge, full width, as tall as the content up to the size limit. Not affected by direction.
bui-drawer--sm|md|lg|xl<dialog>Width for start and end (18rem, 24rem (default), 36rem, 48rem), and the maximum height for top and bottom. Never larger than the screen.
bui-drawer--no-backdrop<dialog>Removes the dark area. The page is still locked and inert, and a click outside still closes the drawer (unless static).
bui-drawer__panelfirst childThe visible box. Required, and it must be a direct child.
data-bui-dismissany control insideCloses the nearest drawer when clicked.
data-bui-drawer-open="#id"a button or linkOpens the drawer with that id.

Options

The same options as Dialog (static, keyboard, focus, restoreFocus, url, load, loadOnce), set with data-bui-* attributes or the second argument of BUI.drawer(). See Dialog options for the full table; the defaults are identical.

06. JavaScript API

BUI.drawer(target, options) works exactly like BUI.dialog(): the same options, methods (open, close, toggle, isOpen, destroy) and the same shared BUI.overlay manager. Only the names differ.

Drawer names
ItemName
FactoryBUI.drawer(target, options); BUI.getInstance(el, 'drawer')
Attributedata-bui-drawer; opener data-bui-drawer-open="#id"
Eventsbui:drawer:beforeopen (cancelable), open, beforeclose (cancelable), close, load, loaderror, with the same detail as Dialog
Partsbui-drawer__panel|header|title|body|footer

A drawer can be open on top of a dialog, or a dialog on top of a drawer: they share one stack, so Esc closes the top one first and the page is unlocked only when the last one closes.

07. Responsive Behavior

Start and end drawers are 24rem wide by default and never wider than the screen, so on a phone they fill the width. Top and bottom drawers span the full width and grow with their content up to the size limit, then the body scrolls. A drawer is positioned against the browser window, not against its parent. For a drawer that should look like a page on small screens, use bui-drawer--xl: it is capped at the screen width.

08. Accessibility

A Drawer is a modal dialog, so it follows the same rules as Dialog: the native role="dialog" and modality, an accessible name from aria-labelledby, Esc closing the top overlay only, Tab wrapping inside, focus moving in on open and returning to the opener on close, and animations removed by prefers-reduced-motion.

Drawer specifics

DirectionStart and end swap in RTL, and the slide direction swaps with them. Checked in Chromium for all four placements in LTR and RTL.

NavigationA drawer that holds site navigation should wrap the links in a <nav> with its own label, as in the example.
