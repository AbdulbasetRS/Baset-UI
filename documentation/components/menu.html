Menu

A dropdown of actions opened from a button. It follows the ARIA Menu Button pattern: arrow keys, Home and End, type-ahead, Esc and Tab, with checkable items and RTL-aware placement.

01. Installation & Include

Menu is part of the Core files: assets/css/baset-ui.css (the Menu rules) and assets/js/baset-ui.js (BUI.menu, built on BUI.position). No Extension and no i18n keys are needed: the component has no text of its own.

<link rel="stylesheet" href="assets/css/baset-ui.css">

<button type="button" class="bui-btn" data-bui-menu>Actions</button>
<div class="bui-menu">
    <button type="button" class="bui-menu__item">Edit</button>
    <button type="button" class="bui-menu__item">Duplicate</button>
    <hr class="bui-menu__divider">
    <button type="button" class="bui-menu__item">Delete</button>
</div>

<script src="assets/js/baset-ui.js"></script>

02. Customize

The preview holds the trigger and its menu. Every option maps to a data-bui-* attribute or to a class or ARIA attribute documented in section 04, and the Code Output is the markup in the preview. The menu leaves the preview while open and takes its Light/Dark and RTL/LTR.

03. Default

A button with data-bui-menu and the .bui-menu list directly after it. Items written with only the class get role="menuitem" from the script.

04. Variants & Options

Structure

Menu parts
Class or attributeDescription
bui-menuThe list. Hidden until opened by the script. Gets role="menu" and is named by the trigger (aria-labelledby).
bui-menu__itemAn item: a <button>, an <a href> or another element. Gets role="menuitem" if it has no role.
role="menuitemcheckbox"A toggle item. Use with aria-checked; the script flips it on choice and draws the mark.
role="menuitemradio"One of a set. Choosing it unchecks the others in the same role="group" (or in the menu when there is no group).
bui-menu__headerA label (not an item). Group it with its items using role="group" and aria-labelledby.
bui-menu__dividerA separator line (<hr>); gets role="separator".
aria-disabled="true"A disabled item. The keys can reach it (as the ARIA pattern asks) but choosing it does nothing. A native disabled button is skipped by the keys.
data-bui-keep-openOn an item: the menu stays open after the item is chosen.
data-bui-valueOn an item: its value, sent in the select event.
data-bui-textOn an item: the text used by type-ahead instead of its content.

Options

Menu options
NameTypeDefaultHTML attributeDescription
targetstring""data-bui-targetSelector of the menu element. If empty, the element right after the trigger is used.
placementstring"bottom-start"data-bui-placementSame values as the Popover placements (top, bottom-end, start, end-start ...). start and end swap in RTL.
offsetnumber4data-bui-offsetPixels between the trigger and the menu.
closeOnSelectbooleantruedata-bui-close-on-selectClose after an item is chosen (an item can opt out with data-bui-keep-open).

The menu is as wide as its content (at least --bui-menu-min-width), flips to the other side and shifts to stay inside the screen, and scrolls inside when the room is short. Tokens: --bui-menu-bg, -color, -muted-color, -border-color, -border-width, -divider-color, -radius, -shadow, -padding, -min-width, -max-height, -item-padding-x, -item-padding-y, -item-gap, -item-radius, -hover-bg, -pressed-bg, -disabled-color, -indicator-size, -touch-item-height, -z, -duration, -easing.

06. JavaScript API

HTML: data-bui-menu on the trigger. JavaScript: BUI.menu('#trigger', options). A Menu is positioned by the Positioning Engine and, like a Popover, moves into an open Dialog or Drawer that holds its trigger so it can be used there.

Methods

Menu methods
NameReturnsDescription
open()booleanOpens the menu and focuses the first item. false if it was already open (focus still moves to the first item) or canceled.
close()booleanCloses the menu. false if it is closed or beforeclose was canceled.
toggle()booleanopen() or close().
isOpen()booleanWhether the menu is open.
update()voidPositions the menu again.
destroy()voidCloses without events, removes the listeners and the attributes the script added.

Events

Dispatched on the trigger element; they bubble. detail.source for open and close: click, keyboard, api, select, toggle, escape, tab, outside, focusout, overlay, detached.

Menu events
NameCancelableDescription
bui:menu:beforeopenYesBefore opening.
bui:menu:openNoAfter it is open and the first item is focused.
bui:menu:beforecloseYesBefore closing (also for Esc and outside clicks).
bui:menu:closeNoAfter it is closed.
bui:menu:selectNoAn item was chosen: detail is { item, role, checked, value }.

07. Responsive Behavior

The menu stays inside the viewport (flip and shift, 8px margin, tested from 320px) and never exceeds the room on screen: it scrolls inside when it is taller. On coarse pointers every item is at least 44px tall. A menu whose trigger is scrolled out of view of a scroll container is hidden until the trigger returns. Resizing the preview in the Playground does not change the viewport, so this follows the browser window.

08. Accessibility

Keyboard

Menu keyboard
KeyAction
Enter, Space, Down arrow on the triggerOpens the menu and focuses the first item. Up arrow focuses the last item.
Down / Up arrowNext or previous item, wrapping around. (Horizontal menu: Right / Left, which swap in RTL.)
Home / EndFirst or last item.
A characterType-ahead: focuses the next item whose text starts with what was typed (the buffer resets after 600 ms).
Enter / Space on an itemChooses it.
EscCloses the menu and returns focus to the trigger.
Tab / Shift+TabCloses the menu; focus goes on from the trigger (forward past it, backward before it).

In a vertical menu the horizontal arrow keys do nothing; they flip with the direction only in a horizontal menu.

ARIA

The trigger has aria-haspopup="menu", aria-expanded and aria-controls. The list is role="menu" named by the trigger; items are menuitem, menuitemcheckbox or menuitemradio with aria-checked. Items are focused by script only (tabindex="-1"), so the menu is a single Tab stop. A header gets role="presentation": wrap its items in a role="group" labelled by it. Submenus are not supported.

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). Also not tested: Safari, Firefox and real touch devices.
