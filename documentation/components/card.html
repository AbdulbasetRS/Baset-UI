Card

A bordered container with header, body, footer and media, in four variants and six colors, horizontal layouts and a stretched link. CSS only.

01. Installation & Include

Card is part of the Core stylesheet, so assets/css/baset-ui.css is the only required file. Load the icons Extension only if the content contains an icon, and a Theme if you use one. Order: Core, then Extension, then Theme. No JavaScript is needed.

<!DOCTYPE html>
<html lang="en" dir="ltr" data-bui-theme="default" data-bui-mode="light">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Card</title>
    <link rel="stylesheet" href="assets/css/baset-ui.css">
    <!-- Only when the content contains an icon -->
    <link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">
    <!-- Optional theme -->
    <link rel="stylesheet" href="assets/css/themes/ocean.css">
</head>
<body>
    <article class="bui-card">
        <div class="bui-card__body">
            <h3 class="bui-card__title">Card title</h3>
            <p class="bui-card__text">Card text.</p>
        </div>
    </article>
</body>
</html>

The media in the examples of this page is a small inline SVG made for the page (a declared sample, not a photograph); its colors come from the theme tokens. The titles and texts are sample text. A real project puts its own img or svg inside bui-card__media.

02. Customize

Every option below is a real class documented in section 04. Horizontal layouts take the media and the body as direct children, so the header and footer options are ignored when a horizontal layout is chosen. A color has an effect only together with a variant (Solid, Subtle or Outline), so it is ignored for Default. Stretched link wraps the title in a link that covers the whole card; the inner button stays clickable. The text is sample text.

Horizontal from md

A column on a narrow screen, a row from 768px. Put the media after the body in the source to place it at the end side.

A horizontal card has the media and the body as direct children: a bui-card__header or bui-card__footer would become a column of its own, so put that content inside the body. The media is 12rem wide (at most 45% of the card) and fills the height; use preserveAspectRatio="xMidYMid slice" on an SVG, or the default object-fit: cover of an image. The corners at the media side follow the direction: the same markup is correct in RTL.

Stretched Link

Put a link with bui-card__stretched-link on the title. Its ::after covers the whole card, so a click anywhere on the card follows the link, and the keyboard focus ring is drawn around the whole card.

Clickable card

Click anywhere on the card. The button below keeps its own action.

  • The link must not be positioned, and no positioned element may sit between it and the card (the card is the positioning context). A wrapper with position, transform or filter around the link makes the link cover that wrapper only.
  • Other interactive elements in the card (a, button, input, select, textarea, summary, [role="button"] and [tabindex]) are raised above the stretched link automatically, with zero specificity: a component that positions itself (for example an absolutely positioned close button) keeps its own position and gets only the stacking order. This needs :has(); where it is not supported, all such elements in every card are raised instead.
  • Selecting the text of a stretched card with the mouse is not possible, because the link covers it. Use it for cards whose main purpose is to open one destination.
  • Do not wrap the whole card in an a: it would nest interactive elements.

06. JavaScript API

CSS only, no JavaScript API. Card registers nothing with BUI.register, fires no events and has no options to parse. Card has no internal text, so it adds no translation key to assets/i18n/*.json: the title, text and link text are whatever you write (use data-bui-i18n with your own keys if you translate them).

07. Responsive Behavior

  • Base (below 480px): a card is a column and as wide as its container. In the Grid, bui-row-cols-1 gives one card per row.
  • bui-card--horizontal-sm, -md and -lg turn from a column into a row at 576px, 768px and 992px. bui-card--horizontal is a row at every width, and its media is at most 45% of the card, so the body keeps room at 320px.
  • Long unbroken text wraps inside the card (overflow-wrap: break-word); the card never causes horizontal scrolling of the page.
  • Cards in one Grid row have equal heights at every width. The corners of the media follow the layout: top corners in a column, the start-side corners in a row.
  • The horizontal breakpoints are viewport media queries (not container queries): a horizontal card in a narrow column of a wide screen is still a row.

08. Accessibility

Keyboard

A plain card is not interactive and is not focusable. A stretched link is one tab stop: Tab focuses the link, Enter follows it, and the focus ring surrounds the whole card (drawn inside the card edge so a container with overflow cannot clip it). Buttons and links inside the card are separate tab stops in source order and keep their own Enter and Space behavior; activating one of them does not follow the stretched link.

ARIA and semantics

  • Use article for a self-contained card (a post, a product), or div/li otherwise. Card adds no role.
  • Put the stretched link on the title, inside a heading of the right level, so the link name is the title and the card appears in the heading outline. Do not put the link on an empty element.
  • Give media meaningful alt text, or alt="" when it is decorative. An SVG that carries meaning needs role="img" and an aria-label.
  • Meaning never depends on color alone: a colored card still needs its words (for example "Error:") in the text.

Contrast

Measured in Chromium for every variant and color (title, subtitle, text, header and footer), in Light and Dark, with the default and ocean themes: 524 samples together with the List Group fixtures, the lowest text contrast is 5.02:1 (above the 4.5:1 AA threshold). The stretched-link ring measures at least 3:1 against the card background on the neutral, three sample cards (neutral, inner controls and solid) in the same themes and modes. Hover and pressed states of list items inside cards stay above 4.5:1 (64 samples).

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). The semantics come from standard elements; how a reader announces a heading that contains a stretched link was not verified.
