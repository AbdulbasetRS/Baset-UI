Radio

A native radio button drawn with CSS: sizes, groups, inline and stacked layouts, and validation states. CSS only.

01. Installation & Include

Radio is part of the Core stylesheet, so assets/css/baset-ui.css is the only file required. It is CSS only and needs no icon Extension: the tick, the dot and the thumb are drawn with CSS. Radio shares its sizes, label, hover, disabled and validation rules with Checkbox and Switch inside the Core stylesheet.

<link rel="stylesheet" href="assets/css/baset-ui.css">

<div class="bui-radio"><input class="bui-radio__input" type="radio" name="group" id="agree"><label class="bui-radio__label" for="agree">Label text</label></div>

02. Customize

Every option below is a real class or attribute documented in section 04.

03. Default

Radio is built on the native <input type="radio">, drawn with appearance: none: it keeps native focus, form submission, the checked and disabled attributes and the Constraint Validation API. The wrapper (bui-radio) holds the input and its label; the input comes before the label.

04. Variants & Options

Markup patterns

Two equivalent patterns. The recommended one links the label with for and id; the alternative makes the wrapper a label that contains the input and a span (no ids needed).

Stacked and inline

Items are stacked by default. bui-radio--inline puts items on one line and wraps them. A long label wraps and the control stays on its first line.

Groups

Radios with the same name form one group: the browser allows one checked at a time and moves the choice with the arrow keys (the direction follows RTL). Label the group with a fieldset and legend, or role="radiogroup" with aria-labelledby.

06. JavaScript API

CSS only, no JavaScript API. Radio registers nothing with BUI.register, fires no events and has no options to parse. It has no internal text, so it adds no key to assets/i18n/*.json: the labels are what you write (use data-bui-i18n with your own keys to translate them). Use the native API: input.checked, the change event.

07. Responsive Behavior

  • The control keeps its size at every width; the label wraps (overflow-wrap: anywhere) so a long label never causes horizontal scrolling.
  • On touch devices (pointer: coarse) the row grows to 44px and the label stretches to the full row height, so the tap target is the whole row. In the default pointer the row is at least 24px high. Verified with a coarse-pointer emulation in Chromium.
  • Inline items wrap onto the next line when the container is too narrow.

08. Accessibility

Keyboard

Tab moves into the group (to the checked radio, or the first one when none is checked); the arrow keys move and check the next or previous radio, and the direction follows the page: in RTL the left arrow moves to the next radio (verified in Chromium). Tab and Shift+Tab move between controls in source order. Clicking the label toggles the control (verified, in both label patterns). The focus ring is the global ring drawn around the control.

ARIA and semantics

  • Radios with the same name form one group; give the group a name with fieldset and legend or role="radiogroup" and aria-labelledby.
  • Every control needs a visible label (linked with for and id, or the wrapper is the label).
  • Help and error text is linked with aria-describedby; an invalid control also gets aria-invalid="true". The invalid style adds a thicker edge, so the state is not only a color.
  • Where it matters, the state does not depend on color alone: the checked state has a tick, a dot or a moved thumb, and the unchecked and checked states differ in shape or position.
  • A native readonly attribute does not exist for this input type, so it is not styled: use disabled, or show the value as text.

Contrast

Measured in Chromium on the manual test page for every size and state in Light and Dark, the default and ocean themes and LTR and RTL (1,024 samples with the other Task 12 pages): label text at least 5.07:1 (AA: 4.5:1); the unchecked border, the checked fill against the page, the tick or dot or thumb against its fill, and the thumb against the track at least 3.73:1 (AA for UI components: 3:1). Disabled controls are exempt and not counted.

Forced colors

The fill and marks are redrawn with system colors (Highlight, HighlightText, ButtonText, Canvas). Checked only with the forced-colors emulation of Chromium (the checked fill, tick, dot and thumb resolved to system colors), not on Windows.

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). Not tested in Safari or Firefox, or on a real touch device.
