Checkbox

A native checkbox drawn with CSS: sizes, indeterminate, inline and stacked layouts, and validation states. CSS only.

01. Installation & Include

Checkbox is part of the Core stylesheet, so assets/css/baset-ui.css is the only file required. It is CSS only and needs no icon Extension: the tick, the dot and the thumb are drawn with CSS. Checkbox, Radio and Switch share one block of rules (sizes, label, hover, disabled and validation) inside the Core stylesheet.

<link rel="stylesheet" href="assets/css/baset-ui.css">

<div class="bui-checkbox"><input class="bui-checkbox__input" type="checkbox" id="agree"><label class="bui-checkbox__label" for="agree">Label text</label></div>

02. Customize

Every option below is a real class or attribute documented in section 04.

03. Default

Checkbox is built on the native <input type="checkbox">, drawn with appearance: none: it keeps native focus, form submission, the checked and disabled attributes and the Constraint Validation API. The wrapper (bui-checkbox) holds the input and its label; the input comes before the label.

04. Variants & Options

Markup patterns

Two equivalent patterns. The recommended one links the label with for and id; the alternative makes the wrapper a label that contains the input and a span (no ids needed).

var all = document.getElementById('ck-all');
var items = ['ck-a', 'ck-b', 'ck-c'].map(function (id) { return document.getElementById(id); });
function sync() {
    var n = items.filter(function (i) { return i.checked; }).length;
    all.checked = n === items.length;
    all.indeterminate = n > 0 && n < items.length;
}
all.addEventListener('change', function () { items.forEach(function (i) { i.checked = all.checked; }); sync(); });
items.forEach(function (i) { i.addEventListener('change', sync); });
sync();

The inline style in the example only indents the children (docs layout, not a library class). The script is page code.

06. JavaScript API

CSS only, no JavaScript API. Checkbox registers nothing with BUI.register, fires no events and has no options to parse. It has no internal text, so it adds no key to assets/i18n/*.json: the labels are what you write (use data-bui-i18n with your own keys to translate them). Use the native API: input.checked, the change event, input.indeterminate.

07. Responsive Behavior

  • The control keeps its size at every width; the label wraps (overflow-wrap: anywhere) so a long label never causes horizontal scrolling.
  • On touch devices (pointer: coarse) the row grows to 44px and the label stretches to the full row height, so the tap target is the whole row. In the default pointer the row is at least 24px high. Verified with a coarse-pointer emulation in Chromium.
  • Inline items wrap onto the next line when the container is too narrow.

08. Accessibility

Keyboard

Space toggles the checkbox. Tab and Shift+Tab move between controls in source order. Clicking the label toggles the control (verified, in both label patterns). The focus ring is the global ring drawn around the control.

ARIA and semantics

  • The native input exposes the checked state. An indeterminate checkbox is announced as mixed by the browser; do not add aria-checked to a native checkbox.
  • Every control needs a visible label (linked with for and id, or the wrapper is the label).
  • Help and error text is linked with aria-describedby; an invalid control also gets aria-invalid="true". The invalid style adds a thicker edge, so the state is not only a color.
  • Where it matters, the state does not depend on color alone: the checked state has a tick, a dot or a moved thumb, and the unchecked and checked states differ in shape or position.
  • A native readonly attribute does not exist for this input type, so it is not styled: use disabled, or show the value as text.

Contrast

Measured in Chromium on the manual test page for every size and state in Light and Dark, the default and ocean themes and LTR and RTL (1,024 samples with the other Task 12 pages): label text at least 5.07:1 (AA: 4.5:1); the unchecked border, the checked fill against the page, the tick or dot or thumb against its fill, and the thumb against the track at least 3.73:1 (AA for UI components: 3:1). Disabled controls are exempt and not counted.

Forced colors

The fill and marks are redrawn with system colors (Highlight, HighlightText, ButtonText, Canvas). Checked only with the forced-colors emulation of Chromium (the checked fill, tick, dot and thumb resolved to system colors), not on Windows.

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). Not tested in Safari or Firefox, or on a real touch device.
