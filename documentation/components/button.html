Button

A clickable control in four variants, six semantic colors and three sizes. CSS only, on a button, a link or an input.

01. Installation & Include

Button is part of the Core stylesheet, so assets/css/baset-ui.css is the only required file. Load the icons Extension only if a button contains an icon, and a Theme if you use one. Order: Core, then Extension, then Theme. No JavaScript is needed.

<!DOCTYPE html>
<html lang="en" dir="ltr" data-bui-theme="default" data-bui-mode="light">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Button</title>
    <link rel="stylesheet" href="assets/css/baset-ui.css">
    <!-- Only when a button contains an icon -->
    <link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">
    <!-- Optional theme -->
    <link rel="stylesheet" href="assets/css/themes/ocean.css">
</head>
<body>
    <button type="button" class="bui-btn">Save changes</button>
</body>
</html>

02. Customize

Every option below is a real class or attribute documented in section 04. The label text in the examples is sample text. Full width does not apply to an icon-only button, and input cannot hold an icon or a spinner, so those two options are ignored for it.

03. Default

With no modifier, .bui-btn is a solid, primary, medium button.

Component tokens

The tokens are declared on :root, on any [data-bui-mode] and on any [data-bui-theme] element, so a Theme or a container can override them (a Theme only has to redefine tokens). Colors are not component tokens: they follow the semantic color tokens through the color modifiers, so a Theme that redefines --bui-color-primary restyles every primary button. Names that contain _ (such as --bui-btn-_bg) are internal and not part of the API.

05. Examples

Buttons with icons

Icons come from the icons Extension and are decorative (aria-hidden="true"). An icon-only button must carry aria-label on the button itself. In a right-to-left page the icon moves to the other side automatically; a directional icon (such as an arrow) also needs bui-icon-flip-rtl.

Link and input elements

Open the report

Use <a> for navigation and <button> for actions. <input type="button"> supports variants, colors, sizes, full width and disabled, but it cannot show an icon or the loading spinner because an input cannot contain elements.

Loading while saving

Click the button: it shows the loading state for two seconds.

const button = document.querySelector('[data-demo-save]');
button.addEventListener('click', () => {
    if (button.getAttribute('aria-busy') === 'true') return; // aria-busy blocks the pointer, not Enter or Space
    button.setAttribute('aria-busy', 'true');
    saveChanges().finally(() => button.removeAttribute('aria-busy'));
});

The library has no JavaScript API for this: you set and remove aria-busy yourself. This pattern keeps keyboard focus on the button. If you prefer, add disabled as well: it blocks every kind of activation, but the browser then moves focus away from the button.

06. JavaScript API

CSS only, no JavaScript API. Button registers nothing with BUI.register, fires no events and has no options to parse. The state hooks are plain attributes (disabled, aria-disabled, aria-busy) that your own code can set and remove, as in the loading example above.

The only optional link to the JavaScript Core is translation: a text inside a button can use data-bui-i18n="common.loading", which the Locale Manager fills (see Internationalization). No key was added for Button: it reuses common.loading.

07. Responsive Behavior

Button has no breakpoint-specific styles; it follows its container.

  • The label wraps onto several lines instead of overflowing a narrow container (tested down to a 320px viewport), and the button grows taller.
  • A button is inline by default. Add bui-btn--block for full width, or use the layout utilities (for example bui-d-flex with bui-flex-wrap and bui-gap-2) to arrange several buttons.
  • On touch devices (pointer: coarse) the minimum height rises to 40px (sm), 44px (md) and 48px (lg), and an icon-only button becomes square at the same size. The small size on touch is below the 44px recommendation and above the 24px WCAG 2.2 AA minimum.
  • Hover styles apply only when the device can hover.
  • To stack a row of related buttons on small screens, use Button Group with bui-btn-group--stack-{sm|md|lg}.

08. Accessibility

Keyboard

Keyboard behavior of Button
ElementKeysBehavior
button, input type="button"Tab, Enter, SpaceTab focuses it, Enter and Space activate it.
a with hrefTab, EnterEnter follows the link. Space does not activate a link (browser behavior).
disabled-Not focusable and not activated.
aria-busy="true" aloneTab, Enter, SpaceStill focusable and still activated by the keyboard. Guard in your handler, or add disabled.

Keyboard focus shows the global focus ring. Focus is not lost on hover or active states.

ARIA

  • Use native elements first. A link used as a button (an action) needs role="button" and its own Space handling; prefer <button> for actions.
  • An icon-only button needs aria-label on the button. The icon inside has aria-hidden="true". Translate the label with data-bui-i18n-attr="aria-label:{key}".
  • A disabled link has no href, role="link" and aria-disabled="true". Setting only aria-disabled on a link that still has an href does not stop keyboard navigation.
  • aria-busy="true" marks the loading state. Because screen readers rarely announce it on a button, add a visually hidden text (common.loading) inside the button, as in section 04.
  • Meaning never depends on color alone: the link variant is underlined, the disabled state also changes opacity and the cursor, and loading shows a spinner.

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar): the semantics above come from native elements and standard attributes, but how each reader announces the loading text and the disabled link was not verified.

Contrast and motion

Measured in Chromium for every variant, color and size in the rest, hover, active, focus-visible and loading states, in Light and Dark, with the default and ocean themes, in both directions (2,984 samples). The lowest text contrast is 5.02:1 (solid warning, Light), above the 4.5:1 AA threshold. The focus ring is at least 6.01:1 against the page and the border of an outline button at least 5.02:1 (3:1 is required). The check measured computed colors; it does not replace a review with a contrast tool on your own Theme.

Disabled buttons are exempt from the WCAG contrast requirement and keep the opacity from --bui-btn-disabled-opacity. With prefers-reduced-motion: reduce the spinner is slowed to one turn per two seconds instead of stopped, because it is a status indicator, and color transitions are shortened by the duration tokens. Forced colors mode was only checked with the Chromium emulation (borders stay drawn, including the transparent ones), not on a real Windows high contrast theme.
