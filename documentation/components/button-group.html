Button Group

Joins related buttons in a row or a column, with joined borders and corners that follow the page direction. CSS only.

01. Installation & Include

Button Group is part of the Core stylesheet, together with Button, so assets/css/baset-ui.css is the only required file. Load the icons Extension only if a button contains an icon. No JavaScript is needed.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<!-- Only when a button contains an icon -->
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<div class="bui-btn-group" role="group" aria-label="Calendar view">
    <button type="button" class="bui-btn bui-btn--outline">Day</button>
    <button type="button" class="bui-btn bui-btn--outline">Week</button>
    <button type="button" class="bui-btn bui-btn--outline">Month</button>
</div>

02. Customize

Every option below is a real class or attribute documented in section 04. The button labels are sample text. The Stack below option reacts to the width of the browser window, not to the width of the preview frame, because media queries follow the viewport; resize the window to see it.

03. Default

A group is a horizontal row of direct .bui-btn children. It needs role="group" and an aria-label that names the set.

Joints and corners

  • Outline, ghost and link buttons overlap their borders by one border width, so a shared edge is drawn once.
  • Solid buttons share one color, so the joint is a hairline in the text color of the button (--bui-color-*-contrast) instead of an overlap you cannot see.
  • Corners use logical properties: in a right-to-left page the first button is on the right and it is the one with the rounded start corners.
  • The hovered, focused or pressed button is raised above its neighbors so its border and focus ring are never covered.

Component tokens

A group has no tokens of its own. Corner radius and joint width come from --bui-btn-radius and --bui-btn-border-width, so a Theme that changes them changes the groups too. The internal flags --bui-btn-group-_h and --bui-btn-group-_v are not part of the API.

06. JavaScript API

CSS only, no JavaScript API. Button Group registers nothing with BUI.register, fires no events and has no options to parse. It does not move focus between buttons: each button stays in the normal Tab order.

07. Responsive Behavior

A group is a row by default and never wraps, so keep the number and length of its buttons within the width of the smallest screen you support, or stack it.

Responsive behavior of Button Group
ClassBelow the breakpointFrom the breakpoint
bui-btn-groupRowRow
bui-btn-group--verticalColumnColumn
bui-btn-group--stack-smColumnRow from 576px
bui-btn-group--stack-mdColumnRow from 768px
bui-btn-group--stack-lgColumnRow from 992px
  • The stack is mobile first: the column is the base style and a min-width media query restores the row.
  • In a column the buttons have the width of the widest button. Use the layout utilities around the group to change that.
  • The size of the buttons on touch devices follows Button.
  • The breakpoint reacts to the browser window, so a narrow container inside a wide window does not stack.

08. Accessibility

Keyboard

A group adds no keyboard behavior. Every button is a separate Tab stop, and Enter and Space activate the focused button (Enter only for a link). Arrow keys do nothing. A set of controls that should be one Tab stop with arrow-key navigation is a toolbar, which this component is not.

ARIA

  • role="group" and an aria-label (or aria-labelledby) are required. Without a name the group conveys nothing.
  • Each button follows the rules of Button: icon-only buttons need aria-label.
  • The group does not set a pressed or selected state. Toggle behavior is out of scope.
  • Focus is never hidden: the focused button is raised above its neighbors, so the focus ring is fully visible.
  • The order in the DOM is the reading and Tab order in both directions: in a right-to-left page the first button is drawn on the right.

Screen reader

Not tested with a screen reader. The group name is expected to be announced when focus enters the group, as for any role="group", but this was not verified.
