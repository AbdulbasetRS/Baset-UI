Progress

A bar that shows how far a task has come, determinate or indeterminate, in six colors and three sizes, with a label inside or outside and optional segments.

01. Installation & Include

Progress is part of the Core stylesheet and works with no JavaScript when you set the value in the markup. The optional Core JavaScript (assets/js/baset-ui.js) adds BUI.progress(el).set(value), which updates the value, the ARIA attributes and an optional text together. A Theme is optional. Order: Core, then Theme.

<!DOCTYPE html>
<html lang="en" dir="ltr" data-bui-theme="default" data-bui-mode="light">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Progress</title>
    <link rel="stylesheet" href="assets/css/baset-ui.css">
    <!-- Optional theme -->
    <link rel="stylesheet" href="assets/css/themes/ocean.css">
</head>
<body>
    <div class="bui-progress" role="progressbar" aria-label="Upload"
         aria-valuenow="40" aria-valuemin="0" aria-valuemax="100"
         style="--bui-progress-value: 40">
        <div class="bui-progress__bar"></div>
    </div>

    <!-- Only for BUI.progress(el).set(value) -->
    <script src="assets/js/baset-ui.js"></script>
</body>
</html>

02. Customize

Every option is a real class or value documented in section 04. The value is a sample number. Indeterminate removes aria-valuenow and the value, the same state you get from set(null). The label inside the bar is hidden at the small size and in indeterminate mode, because there is no room or no value. Segments show a stack of three parts that add up to the value you choose: Documents takes the chosen value, Images and Other take a fixed share.

03. Default

<div class="bui-progress" role="progressbar" aria-label="Upload" aria-valuenow="40" aria-valuemin="0" aria-valuemax="100" style="--bui-progress-value: 40">
    <div class="bui-progress__bar"></div>
</div>

With no modifier, .bui-progress is a medium primary bar. The width comes from --bui-progress-value (a number from 0 to 100); the ARIA attributes carry the same value for assistive technology. Keep the two equal: the script does this for you.

Each segment is a normal progress bar whose width is its value, so the values are shares of the whole track and should add up to at most 100. Every segment has its own label and its own aria-valuenow; the group names the set. A segment is separated by a thin line (--bui-progress-segment-divider) on its start side, so the order flips in a right-to-left page.

06. JavaScript API

The JavaScript is optional. Without it, Progress works from the markup: you set aria-valuenow and --bui-progress-value yourself. BUI.progress(el) does both in one call and keeps them equal. Decision: it was added because keeping a style value and an ARIA value in step by hand is the most common mistake with a progress bar; the component stays small and has no options.

Add data-bui-progress to start it on load, or call BUI.progress(el).

var bar = BUI.progress(document.querySelector('#upload'));
bar.set(60);      // value, ARIA and text updated together
bar.set(null);    // indeterminate (removes aria-valuenow)
bar.get();        // 60, or null when indeterminate

Text sync

An element with data-bui-progress-text shows the percentage and is updated by set. With an empty value it must be inside the bar; with an id it targets the element with that id (a label outside the bar). The number is formatted with the page language and is redrawn on a language change.

Events

EventWhenDetail

Attributes it adds

If missing, it adds role="progressbar", aria-valuemin="0" and aria-valuemax="100". It cannot invent a name: with no aria-label or aria-labelledby it logs a warning.

07. Responsive Behavior

Progress is block level and fills its container (inline-size: 100%), so it follows the width of whatever holds it, from 320 pixels up. There are no breakpoint rules.

  • The height stays fixed from the size token on every screen.
  • In a segment stack the labels are not truncated: a narrow segment hides its text by clipping (overflow: hidden), so keep the numbers short or use the small size, which hides labels.
  • The outside label row wraps on narrow screens; the name takes the width and the value stays on the end side.
  • Progress is not interactive, so there are no hover or touch rules.

08. Accessibility

Keyboard

Progress is not focusable and has no keyboard behavior. It reports a state; it does not take input.

ARIA

  • role="progressbar" with aria-valuemin, aria-valuemax and, for a determinate bar, aria-valuenow.
  • An indeterminate bar has no aria-valuenow. This is the ARIA way to say the value is unknown, and the CSS uses it as the state.
  • A name is required: aria-label, or aria-labelledby pointing at the visible text.
  • aria-valuetext may be added when the number is not meaningful alone ("3 of 10 files"). The script does not manage it.
  • A value change is not announced by assistive technology on its own. If it matters, update a role="status" region at sensible steps instead of at every percent.
  • The label inside and the track color are not the only carriers of meaning: the number is in the label, the attributes and the text.

Contrast

Measured in Chromium in Light and Dark, with the default and ocean themes, in both directions. The label over the fill is at least 5.02:1 (160 samples) and over the empty track at least 9.96:1 (160 samples); both are above 4.5:1. The fill against the track is at least 3.73:1 (208 samples), above the 3:1 non-text minimum.

Motion

With prefers-reduced-motion: reduce, the indeterminate slide is slowed to 3 seconds and a value change keeps its short transition. It is not stopped; this is the same rule as the Button spinner.

Screen reader

Not tested with a screen reader (NVDA, VoiceOver or similar). The semantics are the standard progressbar pattern; how each reader announces updates was not verified.
