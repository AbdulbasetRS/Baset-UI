Toast

A transient message shown by JavaScript. It reuses the Alert shape, stacks in six logical positions, pauses on hover and focus, and works above an open Dialog.

01. Installation & Include

Toast is part of the Core files: assets/css/baset-ui.css (the Alert and Toast rules) and assets/js/baset-ui.js (BUI.toast). The script builds the toast markup, so you write no HTML. Include the icon Extension (baset-ui-icons.css): the type icon and the close button are drawn with it; without it they stay empty. There is no data-bui-* markup API for toasts: they are created from JavaScript.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<button type="button" class="bui-btn" id="save">Save</button>

<script src="assets/js/baset-ui.js"></script>
<script>
    document.getElementById('save').addEventListener('click', function () {
        BUI.toast.success('Profile saved.');
    });
</script>

02. Customize

The preview holds the trigger buttons. Every option maps to an option of BUI.toast.show() (section 04), and the JavaScript block is exactly what the Show toast button runs. Toasts are page level: they appear at the corner of the browser window, not inside the preview box, and they follow the page's direction and theme, not the preview's RTL/LTR and Light/Dark switches. A toast with actions and no explicit duration stays until it is closed.

03. Default

The smallest call is a type shortcut with a message. The toast leaves after 5 seconds (the default), pauses while the pointer or focus is on it, and can be closed with its button or with Esc.

BUI.toast.success('Profile saved.');

04. Variants & Options

BUI.toast.show(options) takes one plain object. At least a title or a message is required. All text is inserted as text (never as HTML).

05. Examples

Type shortcuts

success, error, warning and info take a message string or an options object, and an optional second object of extra options.

BUI.toast.success('Profile saved.');
BUI.toast.error({ title: 'Upload failed', message: 'The file is larger than 5 MB.' });
BUI.toast.warning('Your session expires in 5 minutes.');
BUI.toast.info('A new version is available.');

With an action

A toast with actions stays until it is closed, so there is time to reach the button. The handler receives the toast handle.

BUI.toast.show({
    type: 'info',
    title: 'Message archived',
    actions: [{
        label: 'Undo',
        onClick: function () { BUI.toast.success('Message restored.'); }
    }]
});

Positions

BUI.toast.show({ message: 'Position: top-start', position: 'top-start' });

Update a toast (simulated progress)

update() changes a shown toast in place. The progress here is simulated with a timer; no real work is done.

var toast = BUI.toast.show({
    type: 'info', title: 'Exporting', message: 'Step 1 of 4', duration: 0, closable: false
});
var step = 1;
var timer = setInterval(function () {
    step += 1;
    if (step > 4) {
        clearInterval(timer);
        toast.update({ type: 'success', title: 'Export complete', message: 'All 4 steps finished.', duration: 3000, closable: true });
        return;
    }
    toast.update({ message: 'Step ' + step + ' of 4' });
}, 900);

Queue

Each position shows at most max toasts (5 by default). The others wait and appear as space frees up. This button asks for 8 at the same position.

for (var i = 1; i <= 8; i += 1) {
    BUI.toast.show({ message: 'Toast ' + i, position: 'top-end', duration: 4000 });
}

Above a Dialog

A modal dialog makes everything outside it inert. While a Dialog or Drawer is open, the toast region moves inside the top one, so its toasts stay readable and clickable. Open the dialog and press the button inside.

Dialog with a toast

The toast appears above this dialog and can be closed with its button or Esc.

 
BUI.toast.warning({ title: 'Inside a dialog', message: 'Esc on a toast closes the toast, not the dialog.', duration: 0 });

Global defaults

Not run on this page (it would change the other demos). It applies to every later call:

BUI.config({ toast: { position: 'bottom-center', duration: 8000, max: 3 } });

06. JavaScript API

BUI.toast is a manager, not a per-element component: there is nothing to initialize or destroy. Toasts are never created from markup.

document.addEventListener('bui:toast:hide', function (e) {
    if (e.detail.reason === 'timeout') { /* nobody reacted to it */ }
});

How the region works

  • One live region (.bui-toast-region) is created when the first toast is shown and removed after the last one has left, so no element or timer stays behind. The first toast is added about 50 ms after the region exists, because assistive technology announces changes only inside a region that is already rendered.
  • The region is a popover="manual" element, so it is in the browser top layer. Without the Popover API it is a fixed element using --bui-toast-z.
  • When a Dialog or Drawer opens, the region moves inside the topmost open one and back to body when none is open (see Overlay Manager on the Dialog page). Toasts already shown do not replay their entrance.
  • The newest toast goes next to the screen edge: first in a top stack, last in a bottom stack.

07. Responsive Behavior

The toast is as wide as --bui-toast-width (24rem) but never wider than the window minus the offset on both sides, so at 320px it is 288px wide. The position is the same at every breakpoint. If the toasts of one position are taller than the window the stack scrolls inside itself; the page never gets a horizontal scrollbar. Toasts use the safe stacking of the browser top layer, so on phones they sit above everything, including an open Dialog. Long text wraps.

08. Accessibility

Keyboard

Toast keyboard behavior
KeyBehavior
Tab / Shift+TabToasts are in the document order at the end of body (or at the end of the open Dialog), so Tab reaches their buttons last. Focus is never moved to a toast automatically.
Enter / SpaceActivates the focused action or close button.
EscOn a focused toast: closes that toast (and only that: an open Dialog stays open). Disabled when closable is false.

ARIA and screen readers

  • The single region has role="region", an aria-label from i18n (toast.region) and aria-live="polite". Each toast is role="status"; danger toasts are role="alert" (assertive).
  • Each toast starts with a visually hidden type word (Success, Error, ...) from i18n (alert.type*), so the type is not carried by color or icon alone.
  • The close button name comes from common.close. The language of the toast texts you pass is your responsibility.

Time and focus

  • The timer pauses while the pointer is over a toast or focus is inside it, and resumes with the remaining time.
  • A toast with actions does not close by itself unless you give a duration (WCAG 2.2.1). Prefer duration: 0 for anything the user must act on, and never put the only way to complete a task in a timed toast.
  • Focus is never stolen. If a focused toast leaves, focus returns to the element it came from (when it still exists).
  • The timer runs while the tab is in the background.

Motion

Enter and exit animations use the duration token, so they stop under prefers-reduced-motion.

Warning

Not tested: real screen readers (NVDA, JAWS, VoiceOver, TalkBack): how they announce the region, whether an assertive toast is read twice inside the polite region, and the timing of the first toast. Also untested: Safari and Firefox, touch devices.
