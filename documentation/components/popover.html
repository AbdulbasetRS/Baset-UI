Popover

A small floating panel next to a trigger. It flips and shifts to stay on screen, closes on Esc or an outside click, and also works inside an open Dialog.

01. Installation & Include

Popover and the Positioning Engine are part of the Core files: assets/css/baset-ui.css (the Popover rules) and assets/js/baset-ui.js (BUI.popover and BUI.position). No Extension and no i18n keys are needed: the component has no text of its own (the title and content are yours).

<link rel="stylesheet" href="assets/css/baset-ui.css">

<button type="button" class="bui-btn" data-bui-popover
    data-bui-title="Delivery" data-bui-content="Orders placed before noon ship the same day.">
    Delivery info
</button>

<script src="assets/js/baset-ui.js"></script>

02. Customize

The preview holds one trigger button. Every option maps to a data-bui-* attribute (section 04) and the Code Output is exactly the markup in the preview. The panel opens above the page (it leaves the preview while open), and takes the Light/Dark and RTL/LTR of the preview. Resizing the preview width does not change the viewport, so flipping and shifting follow the browser window, not the preview.

03. Default

A trigger with data-bui-title and data-bui-content. The panel is built from them (as text, never HTML), opens below the trigger on click, moves focus into itself, and closes with Esc, an outside click, or the trigger.

04. Variants & Options

Structure

Instead of the two attributes you can write the panel yourself, for rich content, and point at it with data-bui-target, or put it directly after the trigger.

<button type="button" class="bui-btn" data-bui-popover data-bui-target="#help">Help</button>

<div class="bui-popover" id="help">
    <div class="bui-popover__header"><div class="bui-popover__title">Need help?</div></div>
    <div class="bui-popover__body">
        <p>Any content, including links and buttons.</p>
        <a class="bui-btn bui-btn--sm" href="#">Contact support</a>
    </div>
</div>
Popover parts
ClassDescription
bui-popoverThe panel. Hidden until opened by the script.
bui-popover__headerOptional. Holds the title; separated from the body by a line.
bui-popover__titleThe title. Names the panel (aria-labelledby is added for you).
bui-popover__bodyThe content. Scrolls inside when the room on screen is short.
bui-popover__arrowThe arrow. Created by the script when arrow is true; you may place it yourself as the first child.

Placements

start and end are logical: they swap in RTL. The panel gets data-bui-side (the physical side where it is: top, bottom, left, right) and data-bui-placement (the resolved logical placement, after any flip).

Placements
ValueWhere the panel goes
topAbove, centered. Same for bottom.
top-start / top-endAbove, aligned to the start or the end edge of the trigger. Same for bottom-*.
start / endBeside the trigger, vertically centered. In LTR start is the left side.
start-start / start-endBeside the trigger, aligned to its top or bottom edge. Same for end-*.

Design tokens

Themes can change the look with --bui-popover-bg, -color, -border-color, -border-width, -radius, -shadow, -padding-x, -padding-y, -max-width, -arrow-size, -title-font-weight, -z, -duration and -easing.

Shows on pointer hover and on keyboard focus. The panel stays open while the pointer is over it. Use it only for extra information: the content must not be needed to use the page (touch devices have no hover).

Inside a Dialog

A popover opened from inside an open Dialog or Drawer is placed inside it, so it can be focused and clicked. Esc closes the popover first, then the Dialog.

06. JavaScript API

HTML: add data-bui-popover (initialized by BUI.init()). JavaScript: BUI.popover('#id', options) returns the instance, or null if the selector finds nothing.

Methods

Popover methods
NameReturnsDescription
show()booleanOpens the panel. false if it is already open or a beforeshow listener canceled it.
hide()booleanCloses the panel. false if it is closed or beforehide was canceled.
toggle()booleanshow() or hide().
isOpen()booleanWhether the panel is open.
update()voidPositions the panel again (after its content or the layout changed by script).
destroy()voidCloses without events, removes the listeners, the attributes the script added and a built panel.

Events

Events are dispatched on the trigger element and bubble. detail.source is why it happened: click, hover, focus, api (a method call), escape, outside, focusout, tab, overlay (a Dialog or Drawer opened or closed) or detached (the trigger left the page).

Popover events
NameCancelableDescription
bui:popover:beforeshowYesBefore opening.
bui:popover:showNoAfter the panel is open and positioned.
bui:popover:beforehideYesBefore closing (also for Esc and outside clicks).
bui:popover:hideNoAfter the panel is closed.

Events are named without a hyphen between the words (beforeshow), like the Dialog events.

Positioning Engine (internal API)

BUI.position(anchor, floating, options) is the engine Popover and Menu use, and later Select, Date Picker and Tooltip will use. It is documented here for the library's own components. It is internal: it may change before 1.0 without a major version. It returns { update(), getPlacement(), destroy() }, or null for invalid arguments.

BUI.position options
NameTypeDefaultDescription
placementstring"bottom"As in the placements table above.
offsetnumber8Pixels between anchor and floating element.
paddingnumber8Pixels kept free at the screen edges.
flipbooleantrueUse the opposite side when the chosen one lacks room and the opposite has more.
shiftbooleantrueKeep the element inside the screen along the edge (and, if no side fits, along the main axis).
arrowElement | nullnullAn arrow element (a square). It slides along the edge to point at the anchor center and the offset grows to fit it.
arrowPaddingnumber8Minimum distance of the arrow from the corners.
autoUpdatebooleantrueUpdate on scroll of the anchor ancestors and the window, on resize and when either element changes size.
hideWhenClippedbooleantrueSet data-bui-detached while the anchor is scrolled out of view of a scroll container or the screen.
onUpdatefunctionnullCalled after every update with { placement, side, x, y, detached }.

The engine owns these inline properties of the floating element: position, margin, right, bottom, left, top. It sets data-bui-side, data-bui-placement, data-bui-detached and the custom properties --bui-position-available-width and --bui-position-available-height (the room left on the chosen side, used by CSS to limit the size). destroy() removes all of them and every listener. The coordinates are physical because they come from measurements; start and end follow the direction of the anchor. The floating element must be rendered (not display: none) when it is measured, and must not sit inside an ancestor with a transform.

var engine = BUI.position(buttonEl, panelEl, { placement: 'bottom-start', offset: 6 });
// later
engine.update();
engine.destroy();

07. Responsive Behavior

The panel never grows wider than --bui-popover-max-width (18rem) or than the room on the screen, and it flips or shifts so it stays inside the viewport with an 8px margin (tested from 320px). Its body scrolls inside when the room above or below is short. When the trigger is scrolled out of view of a scroll container, the panel is hidden until it is visible again. On touch devices there is no hover: a hover trigger opens on tap (the browser sends the mouse events) but this was not tested on a real device, so use click for anything that matters.

08. Accessibility

Keyboard

Popover keyboard
KeyAction
Enter / Space on the triggerOpens (click trigger) and moves focus into the panel.
EscCloses the topmost popover or menu only, and returns focus to the trigger. An open Dialog behind it stays open.
Tab from the last controlCloses the panel; focus goes to the trigger and then on to the next element after it. Shift+Tab from the first control closes and stays on the trigger.

ARIA

The trigger gets aria-haspopup="dialog", aria-expanded and aria-controls. The panel is a non-modal role="dialog" named by its title (aria-labelledby) or by aria-label; without a name the script warns. The arrow is aria-hidden. Use a real <button> as the trigger.

Screen reader

Not tested with a screen reader. Hover and focus triggers keep the panel open while the pointer is over it and Esc closes it (WCAG 1.4.13), but their content is not announced on its own: keep anything essential outside of them. Also not tested: Safari and Firefox, and real touch devices.
