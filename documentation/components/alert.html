Alert

An inline message that stays in the page flow. Six semantic colors, an icon, a title, a description, actions and a dismiss button with a leaving animation.

01. Installation & Include

Alert is part of the Core files: assets/css/baset-ui.css draws it. assets/js/baset-ui.js is only needed for the dismiss button (data-bui-dismiss="alert") and the BUI.alert API; an alert without a dismiss button is CSS only. The icon and the dismiss button use the icon Extension (baset-ui-icons.css), and the dismiss button is the Close Button. Load order: Core CSS, icons Extension, optional Theme; Core JS at the end of body.

<link rel="stylesheet" href="assets/css/baset-ui.css">
<link rel="stylesheet" href="assets/css/extensions/baset-ui-icons.css">

<div class="bui-alert bui-alert--success" role="status">
    <i class="bui-icon-regular bui-icon-check-circle bui-alert__icon" aria-hidden="true"></i>
    <div class="bui-alert__content">
        <p class="bui-alert__title">Saved</p>
        <div class="bui-alert__description">Your changes were saved.</div>
    </div>
    <button type="button" class="bui-btn-close bui-alert__close" data-bui-dismiss="alert" aria-label="Close"
        data-bui-i18n-attr="aria-label:common.close"><i class="bui-icon-regular bui-icon-x" aria-hidden="true"></i></button>
</div>

<script src="assets/js/baset-ui.js"></script>

Note

The Toast (Toast page) is this same alert shown in a floating stack by BUI.toast. Changing the --bui-alert-* tokens restyles both.

02. Customize

Every option below is a real class or attribute documented in section 04. Pressing the dismiss button removes the alert after its leaving animation; change any option to bring it back. The Responsive Preview width, Light/Dark and RTL/LTR switches apply to the preview box only.

03. Default

The default alert uses the primary color. Without a color modifier it is the same as bui-alert--primary.

Colors come from the semantic color tokens through the modifiers, so a Theme restyles every alert.

Created with JavaScript

Use BUI.toast for messages that appear and leave by themselves. For an alert inserted into the page, build the markup, add it to the DOM and give it a role before inserting so assistive technology announces it:

var host = document.querySelector('#form-errors');
host.innerHTML =
    '<div class="bui-alert bui-alert--danger" role="alert">' +
    '<i class="bui-icon-regular bui-icon-x-circle bui-alert__icon" aria-hidden="true"></i>' +
    '<div class="bui-alert__content"><p class="bui-alert__title">Check the form</p>' +
    '<div class="bui-alert__description">Two fields need your attention.</div></div></div>';

06. JavaScript API

BUI.alert(target) returns the instance for an element (the same one if called again). It has no options. Use it to close an alert from code or to listen to its events.

var alertEl = document.querySelector('#saved-alert');
var instance = BUI.alert(alertEl);
alertEl.addEventListener('bui:alert:close', function () { /* the element is removed right after this */ });
instance.close();

Methods

Alert methods
NameReturnsDescription
close()booleanStarts the leaving animation, fires close, removes the element from the page and destroys the instance. Returns false if it is already closing or beforeclose was canceled.
isClosed()booleantrue once close() was accepted.
destroy()voidCancels a pending close, removes is-closing and the role the component added. An alert that was already removed from the page is not put back.

Events

DOM events on the alert element, bubbling.

Alert events
NameCancelableDescription
bui:alert:beforecloseyesBefore closing starts. preventDefault() keeps the alert.

Note

data-bui-dismiss without a value belongs to Dialog and Drawer (it closes the nearest overlay). Inside a dialog, a button with data-bui-dismiss="alert" closes only its alert. Since Task 15 a Dialog or Drawer reacts only to an empty data-bui-dismiss (or its own type), so other values never close the overlay by accident.

07. Responsive Behavior

The alert is a flex row that fills the width of its container, with no breakpoint rules. Text wraps (overflow-wrap: anywhere), so long words and URLs stay inside; the actions wrap onto several lines; the dismiss button keeps its size. Down to 320px nothing overflows horizontally. On touch screens (pointer: coarse) the Close Button grows to its larger touch target.

08. Accessibility

Keyboard

Alert keyboard behavior
KeyBehavior
Tab / Shift+TabMoves through the actions, links and the dismiss button in DOM order. An alert itself is not focusable.
Enter / SpaceActivates the focused button (the dismiss button closes the alert).

ARIA and screen readers

  • role="alert" (assertive) is for messages that need immediate attention: errors and warnings. Use role="status" (polite) for everything else. The component adds the matching role only when the element has none.
  • A live role announces an alert that is inserted or changed after load; an alert already present when the page loads is read in normal reading order. Set the role before inserting a new alert.
  • The type is never carried by color alone: the icon shape and the title differ. If the title does not say the type (for example "Saved" is clear, "Heads up" is not), add a visually hidden prefix with bui-visually-hidden.
  • The icon is decorative (aria-hidden="true"). The dismiss button gets its name from aria-label, translated by data-bui-i18n-attr="aria-label:common.close".

Focus

Dismissing an alert does not move focus: if the dismiss button had focus, the browser drops it to the start of the page when the element is removed. When that matters (a form error list, for example) move focus yourself in a bui:alert:close listener.

Motion and colors

The leaving animation uses the duration token, so it stops under prefers-reduced-motion. Text contrast was measured on every color in Light and Dark, default and ocean themes (see the Task 15 report). In Forced Colors mode the alert keeps a visible border.

Not tested: real screen readers (NVDA, JAWS, VoiceOver), Safari and Firefox, touch devices.
